# 하위 에이전트 활용

작업 시작과 하위 작업 배정 전에 `fullops.json.subagent_level`을 읽는다. 신규 setup은 `lite`, 기존 설정 누락은 `off`다. 테스트 레벨은 `test_level`로 별도 선택한다.

| 레벨 | 선택형 위임 범위 | 부모별 동시 하위 작업 예산 |
|---|---|---|
| `off` | 부모가 직접 처리 | 0 |
| `lite` | 읽기 전용 조사·리뷰 | 1 |
| `standard` | 파일 소유권을 나눈 병렬 구현·조사·리뷰 | 2 |
| `full` | 독립 작업을 넓게 병렬 처리 | 4 |

숫자는 부모가 관리하는 운영 예산이며 호스트 전체 프로세스의 강제 제한이 아니다. 완료한 하위 작업은 예산에서 제외한다. coor의 필수 역할 배정과 최종 수락에 필요한 독립 snapshot 리뷰는 이 선택형 위임과 구분해 기존 계약을 유지한다.

## 배정과 취합

1. 준비·전달·취합 비용보다 줄일 수 있는 대기 시간이 큰 독립 작업에만 위임한다. 짧은 단일 파일 수정, 같은 파일의 연속 수정은 직접 처리한다.
2. 하위 지시에 `Purpose: research|review|implementation`, 현재 과제 키, `Subagent level: <선택값>`, `Test level: <선택값>`, 읽을 근거, 파일 소유권, 완료 조건을 적는다. `lite`의 조사·리뷰는 읽기 전용으로 명시한다. 부모가 할 작업도 함께 정해 중복 탐색·검사를 피한다.
3. 같은 워크트리의 호스트 서브에이전트는 호스트가 제공할 때 사용한다. 병렬 구현은 겹치지 않는 파일만 맡기고 Git 커밋·브랜치 변경은 부모 한 명이 처리한다. Git 작업까지 독립시키려면 별도 워크트리의 Orca worker를 사용한다.
4. 부모의 승인 범위·보안·테스트 레벨·원본 보존 조건을 그대로 전달한다. 역할·목적 제한과 런타임 깊이 제한 안에서 위임하고, 하위 작업의 재위임으로 동시 예산을 늘리지 않는다. 필수 독립 리뷰는 기존 `fullops-review`의 작성자 분리·고정 SHA 계약을 따른다.
5. 부모가 하위 결과와 변경 파일·검증 근거를 확인하고 취합한 뒤 완료를 보고한다. 하위 실패·질문은 부모가 처리하며 남은 작업은 담당·재개 조건으로 기록한다. 정상 실행 중인 하위 작업을 임의 종료하지 않는다.

## 이슈 오토모드

오토모드의 하위 작업은 Orca supervised worker로 배정한다. 추적할 수 없는 호스트 내부 서브에이전트로 이슈 작업을 넘기지 않는다. dispatched 부모는 자기 child Run을 만들고 같은 자동 이슈 task key를 spec에 넣는다. FullOps는 Run의 coordinator와 부모 host/Dispatch binding을 확인한 뒤에만 연결한다. 부모는 child Run의 결과를 받고 처리한 뒤 자기 `worker_done`을 보낸다.

하위 작업에도 같은 이슈의 allowlist·소유 epoch·보류·시간/사용량 한도·외부 변경 제한을 적용한다. coor 교체 뒤 이전 하위 작업은 완료·escalation 증거만 전달하고 새 변경을 진행하지 않는다. 재개와 완료 확인에는 부모 Run과 등록된 child Run의 task/worker 근거가 모두 필요하다.

## 설정 변경

`setup.py --repo <레포> --subagent-level <off|lite|standard|full>`로 변경한다. 먼저 `--dry-run --verbose`로 설정과 문서 변경을 확인한다. 진행 중 하위 작업의 회수는 부모가 처리하고, 다음 배정부터 변경값을 사용한다. 호스트가 서브에이전트나 tool hook을 제공하지 않으면 직접 작업하며 미지원 사실을 기록한다.

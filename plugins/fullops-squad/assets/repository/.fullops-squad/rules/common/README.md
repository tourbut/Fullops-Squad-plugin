# FullOps 공통 개발 규칙

규칙 묶음: `fullops-common-0.3.1`

## 적용

현재 Git 레포 루트에 `.fullops-squad/fullops.json`이 있을 때만 적용한다. 작업자와 검토자는 이 문서와 아래 세 규칙을 읽고, `project.md`에 연결된 프로젝트 정본을 확인한다. 같은 과제에서 같은 버전의 문서를 이미 확인했다면 중복 복사하지 않고 근거를 재사용한다.

- [코딩 스타일](coding-style.md): 단순한 설계, 책임과 상태 변경 경계, 오류 처리.
- [테스트](testing.md): 변경 동작의 검증, 재현과 실행 근거, 프로젝트별 기준.
- [보안](security.md): 비밀값, 입력·권한 경계, 위험한 변경의 검토.

이 묶음은 개발 기준 문서이지 자동 검사기나 실행 권한이 아니다. ECC의 플러그인·에이전트·스킬·훅·모델 설정은 설치하지 않으며 전역 호스트 설정을 변경하지 않는다. 파일 배치만으로 호스트의 자동 로딩이나 코드 준수가 보장되지 않는다.

## 프로젝트 기준과 충돌

코딩 스타일·설계 기본값은 프로젝트의 명시적인 언어 관례와 아키텍처 정본을 우선한다. 특정 디렉터리 구조, Repository 패턴, API 응답 형식을 모든 레포에 강제하지 않는다. 테스트 종류·명령·커버리지 목표도 프로젝트 기준을 따른다. 이 규칙을 도입한다는 이유로 기존 요구 수준을 낮추지 않는다.

비밀값 보호, 승인 범위, 리뷰 수락 기준은 작업 지시서나 외부 스킬로 임의 완화하지 않는다. 미해결 critical/high가 있으면 기존 FullOps 리뷰 검사를 통과할 수 없다. 실제 충돌이나 예외는 지시서에 경로·이유·승인 필요 여부를 기록하고, 승인이 필요한 예외는 승인 전 적용하지 않는다.

## 전달과 검토

지시서의 `적용 기준과 예외`에 이 묶음의 식별자, 사용한 프로젝트 문서 경로와 기준 커밋을 적는다. 미커밋 문서는 명시한 스냅샷 경로로 식별한다. 규칙을 수정했다면 같은 식별자만으로 동일한 내용이라고 판단하지 않는다.

worker와 검토자는 동일한 규칙·정본 버전을 읽을 수 있어야 한다. 파일이 없거나 버전이 다르면 준비 커밋 또는 명시적인 스냅샷으로 먼저 일치시킨다. 규칙 변경 시 적용 기준을 다시 확인하고 필요한 검토를 수행한다. `review.py check`는 이 Markdown 묶음의 내용·버전이나 테스트 성공을 자동 검증하지 않으므로 검토자가 보고서에 적용 기준과 근거를 남긴다.

## 보존과 갱신

setup은 없는 파일만 추가하고 기존 규칙·프로젝트 문서·인박스를 보존한다. 기존 레포의 규칙 개정과 연결 문서 갱신은 차이를 검토한 뒤 명시적으로 반영한다. `fullops.json`의 기존 `plugin_version`은 setup 재실행으로 덮어쓰지 않으며 이 묶음의 적용 여부를 증명하지 않는다. 실제 파일과 작업 기준 커밋을 확인한다.

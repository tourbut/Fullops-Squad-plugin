# <묶음 키> — <한 줄 목표>

과제 2개 이상이나 역할 2개 이상에 걸치는 묶음 작업의 의도다. 과제 하나로 끝나는 수정에는 쓰지 않는다. 파일은 `docs/planning/intents/<묶음 키>.md`로 복사하고 front matter는 `deliverables.py --stamp --path docs/planning/intents/<묶음 키>.md`로 쓴다. 사용자가 승인하면 `status`를 `approved`로 바꾸고 `## 승인`에 근거를 적는다. 같은 묶음의 지시서는 `상위 의도`에 이 파일과 맡는 성공 기준 ID를 적는다.

## 배경

지금 상태와 이 작업이 필요해진 계기를 적는다. 사용자 요청·이슈·사용자 테스트·지표 같은 근거를 링크한다.

## 문제

누가 어떤 상황에서 무엇을 하지 못하는지 적는다. 해결 방법은 여기에 쓰지 않는다.

## 바라는 결과

작업이 끝났을 때 사용자에게 달라지는 점을 적는다.

## 성공 기준

관찰할 수 있는 결과로 적는다. "잘 동작한다"처럼 확인할 수 없는 표현은 쓰지 않는다. 큰 틀 검수는 이 기준으로 판정한다. `확인할 흐름`은 요구사항(D02)·시나리오가 생긴 뒤 coordinator가 채운다.

| ID | 기준 | 확인할 흐름 |
|---|---|---|
| S1 | 예: 첫 방문자가 3단계 안에 첫 펫을 만든다 | |

## 대상 사용자와 주요 흐름

대상 사용자와, 이 묶음이 바꾸는 사용자 흐름을 처음부터 끝까지 적는다.

## 제약과 범위 밖

기술·일정·정책 제약과 이번에 하지 않을 것을 적는다.

## 열린 질문

승인 전에 답이 필요한 질문과 담당을 적는다.

## 관련 단계

(선택) 현황판 `board.json` 단계나 D01 사업계획서의 관련 절을 적는다.

## 승인

승인한 사람·날짜·근거(대화·이슈 링크)를 적는다.

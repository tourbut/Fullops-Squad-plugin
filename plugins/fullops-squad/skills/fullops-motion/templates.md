# 모션 템플릿

이슈 [#57](https://github.com/tourbut/Fullops-Squad-plugin/issues/57)에서 고른 공개 프롬프트의 **구조**를 FullOps가 다시 쓴 요약이다. 원문은 싣지 않는다. 원작과 원문의 권리는 각 제작자에게 있고, 출처 라이브러리([JasonZhu.AI](https://jasonzhu.ai/en/prompts/claude-opus-5-5), [데이터](https://github.com/zhuyansen/awesome-opus-5.5-video))도 수록이 사용 허락이 아니라고 밝힌다. 원문이 필요하면 원본 게시물을 직접 연다. 템플릿으로 만든 영상을 공유할 때는 인계 기록과 설명에 `참고: <제목> by <제작자> (<원본 링크>)`를 남긴다.

## 쓰는 법

1. 요청에 가장 가까운 템플릿 하나를 고른다. 섞을 때는 뼈대 하나에 다른 템플릿의 기법만 가져온다.
2. **바꿀 것**만 사용자 주제·브랜드·문구로 바꾸고 **지킬 것**은 그대로 둔다. 주제·문구·브랜드 자산처럼 추정할 수 없는 입력은 먼저 묻는다.
3. 템플릿에 없는 캔버스 규격·길이·FPS·검증은 아래 공통 규약으로 채운다.
4. 코드 전에 장면표(비트 그리드면 비트별)와 핵심 스틸 계획을 보여 준다. 템플릿이 "먼저 보여 달라"는 단계를 두면 그 단계에서 확인받는다.

## 공통 규약

- 단일 `index.html`, 외부 네트워크 없음. 글꼴·음원·이미지는 `videos/<작업>/` 안의 허가된 로컬 파일만 쓴다.
- 모든 시각 상태는 `window.seek(t)`(초)가 계산한다. CSS transition·타이머·프레임 사이 상태를 쓰지 않는다. 비동기로 그리는 캔버스는 그리기가 끝날 때 resolve하는 promise를 돌려준다.
- 스프링은 닫힌 형식의 계단 응답이다. 목표가 여러 번 바뀌면 바뀔 때마다 스프링 하나씩 더해 시간의 순수 함수로 유지한다.
- 실시간 루프(rAF·고정 timestep·파티클)로 쓰인 템플릿은 `seek(t)`에서 상태를 초기화하고 `Math.floor(t * 60 + 1e-6)`번 고정 스텝을 돌려(부동소수 오차로 스텝이 빠지지 않게) 같은 t에 같은 화면을 낸다. 난수는 시드 고정 또는 정해진 패턴 배열로 바꾼다. 오래 걸리면 마지막 스텝 위치부터 이어 계산한다.
- 루프 작품은 `seek(길이)`가 `seek(0)`과 같은 상태를 낸다(커서 위치·속도 포함). 렌더의 마지막 프레임은 `길이 − 1/FPS` 시각이다.
- 비트 동기 작품은 음원의 비트 그리드를 측정해 다운비트에서 시작하고, 큐 시각을 장면표에 적는다.
- 렌더 전 사전 점검: 비트나 장면마다 스틸 한 장씩 뽑아 글자 잘림·겹침·대비·고아 단어를 고친 뒤 전체 렌더로 간다.

## 템플릿 구조

### 0. 한 줄 쇼릴 브리프

모델에게 "이력서용 쇼릴처럼 실력을 다 보여 주라"는 한 문장만 주는 방식이다. 규격·장면·검증이 없으므로 그대로 쓰지 않는다.
- 바꿀 것: 길이, 선택적으로 소개할 대상
- 채울 것: 공통 규약 전체, 캔버스 규격, 장면표. 실제로는 #7의 구조를 뼈대로 삼는다

### 1. UI 상태 모핑 쇼릴

도형 하나가 끊기지 않고 8~12개 UI 상태로 변한다. 크기·모서리·색이 모핑되고 내용은 짧은 블러로 바뀐다. 커서가 실제 클릭과 드래그로 모든 변화를 일으키고, 카메라는 상태마다 화면을 채우도록 줌한다.
- 흐름 예: 버튼 → 로더 → 체크 → 다이내믹 아일랜드 → 플레이어 → 진행 바 스크럽 → 볼륨 슬라이더 → 토글 → 탭 인디케이터 → 차트 → 커맨드 팔레트 → 토스트 → 버튼
- 기법: 탭 인디케이터와 토글 손잡이의 양 끝을 서로 다른 스프링에 태워 늘어나 보이게 한다. 드래그 중에는 값을 커서 위치로 직접 계산하고, 놓으면 그 자리에서 스프링으로 돌아간다. UI 효과음은 측정한 비트 피크에 맞춘다. 4-subframe 모션 블러를 쓴다.
- 금지: 튀는 이징, 파티클 폭발, 글로우, UI 크롬 그라데이션, 아이콘 선 굵기 불일치, 빈 시간, 템플릿 티
- 주의: 카메라가 스케일하는 요소에 `will-change`를 주지 않는다(글자 흐림). 모핑 컨테이너 안에서 바뀌는 글자는 들어오고 나가는 타이밍을 따로 준다.
- 바꿀 것: UI 상태 목록, 흑백 또는 강조색 하나, 음원과 BPM
- 지킬 것: 도형 하나의 모핑, 비트마다 사건, 루프 일치, 비트 그리드를 먼저 확인받는 순서

### 2. 키네틱 아이덴티티 범퍼

포스터 같은 강한 타이포로 고정 메시지 여섯 줄을 비트 순서대로 때린다. 구간이 정해진 서사이고 끝은 브랜드 락업으로 정착한다.
- 구간: 콜드 오픈 → 주장 A → 주장 B(나가는 글자를 마스크로 다음 글자 공개) → 근거 플래시(짧은 모노 문구, 3줄 이하의 가짜 프롬프트 블록) → 브랜드 락업 → 정착과 루프
- 규격: 엄격한 4색 팔레트, 서체 셋(초압축 디스플레이, 그로테스크, 모노). 자간 범위를 정해 둔다.
- 기법: 글리프별 스프링(y·투명도·블러), 120BPM 16분음표 스태거, 시드 고정 글자 스크램블 후 비트에 스냅, 강조 프레임에서만 2~4px 인쇄 어긋남, 비트에 맞춘 펀치인과 스매시 팬만 쓰는 카메라, 4-subframe 모션 블러, 처음 16비트는 비트마다 사건
- 금지: 흔한 AI 상징, 부드러운 그라데이션, 만화 같은 바운스, 파티클 폭발, 기성 HUD, 긴 문장, 고정 메시지 외 슬로건, 보라·파랑 네온, 글래스모피즘
- 바꿀 것: 브랜드명, 메시지 여섯 줄, 모노 문구, 팔레트, 서체
- 지킬 것: 길이와 루프, 구간 서사, 필수 기법, 금지 목록, 주요 비트 스틸 사전 점검

### 3. 연결 요소 하나로 이어지는 모션 시스템

강조색 점 하나가 모든 장면을 잇는다. UI 토글에서 시작해 글자 위 점이 되고, 스프링 그래프를 그리고, 도형으로 커졌다가 엔드카드로 돌아온다.
- 장면: 커서가 토글을 클릭하면 문구가 핵심 단어 하나만 남기고 정리된다 → 점이 그래프로 뛰어 오버슈트 후 수치 콜아웃 옆에 정착 → 점이 원으로 커져 화면을 채우고 안의 사각형이 회전하며 알약 모양으로 늘어남 → 단어들이 점을 공전하다 하프톤 점 필드로 풀림 → 하프톤이 뒤집히며 엔드카드 → 점이 거꾸로 돌아가 첫 프레임과 일치
- 기법: 점의 움직임과 그래프를 같은 스프링 함수로 그린다. 원·사각형·알약은 같은 도형의 상태로 위치와 운동을 이어 간다. 하프톤 점 크기는 강조 점에 반응한다. 화면을 채우는 도형은 네 모서리 너머까지 키운다.
- 금지: 스톡 영상, 그라데이션, 글로우, 파티클, 화면에 없는 요소에서 나오는 동작
- 바꿀 것: 토글 문구, 핵심 단어, 그래프 수치, 공전 단어, 엔드카드 문구, 강조색, 음원
- 지킬 것: 연결 요소 하나, 장면 순서, 비트 맵과 스틸 네 장(토글·그래프·타이포·엔드카드)을 먼저 확인받는 순서

### 4. 조사 기반 제품 런칭 영상

제품 사이트를 직접 조사해 고유 가치를 찾고, 그 제품의 UI·색·서체·모션 언어로 보이는 런칭 영상을 만든다. 콘셉트·카피·속도는 제작자가 정하고, 정상 속도로 다시 보며 검토한다.
- 원작은 HyperFrames 프로젝트로 만든다. FullOps에서는 사용자가 HyperFrames를 지정한 경우에만 그 엔진으로 하고, 아니면 공통 규약의 단일 HTML로 만든다.
- 바꿀 것: 제품 URL과 이름
- 지킬 것: 조사 → 가치 제안 → 브랜드에 충실한 표현 → 정상 속도 검토. 사이트 조사는 외부 네트워크 접근이므로 승인 범위를 확인한다. 브랜드 자산은 사용자가 준 파일이나 사용 허락된 것만 쓴다.

### 5. 제품 쇼릴 재사용 브리프

#0에 "먼저 제품 페이지를 읽고 내용을 직접 쓰라"를 더한 짧은 브리프다.
- 바꿀 것: 제품과 페이지 URL
- 지킬 것: 조사 먼저, 15초 쇼릴 구성. 규격과 검증은 공통 규약과 #7 뼈대로 채운다.

### 6. 실제 자산을 쓰는 제품 소개

실제 제품 스크린샷과 로고를 쓰고, 음악이 있으며 움직임이 음악에 맞는 "데모가 아닌 실제 프로덕션" 수준의 15초 소개다.
- 바꿀 것: 제품, 사용자가 제공한 스크린샷·로고·음원
- 지킬 것: 15초, 음악 동기, 프로덕션 품질 기준. 자산 권리를 확인하고, 자산이 없으면 만들어 넣지 말고 요청한다.

### 7. 구조형 한 문단 쇼릴

첫 1초의 강한 훅 → 서로 다른 기법의 연속(타이포, 도형 놀이, 카메라 이동, 색 전환) → 깔끔하고 기억에 남는 마지막 프레임. 음악에 맞춰 편집한 듯한 속도로 간다. 짧은 브리프(#0·#5·#6)의 기본 뼈대로 쓴다.
- 바꿀 것: 길이, 기법 목록, 마지막 프레임 아이디어
- 지킬 것: 훅 → 기법 → 마무리 구조, 비트에 맞춘 편집

### 8. 코드 합성 사운드트랙 쇼릴

#0의 쇼릴에 사운드트랙을 코드로만 합성하는 조건을 더한다. 샘플·오디오 파일·악기 플러그인 없이 만들고, 모든 컷과 전환이 비트에 맞으며, 음악을 섞은 MP4로 낸다.
- 구현: 합성기(Python·Node 등)로 WAV를 만들고 같은 BPM으로 장면 큐를 계산한다. `render.mjs --audio`로 섞는다.
- 바꿀 것: 길이, 해상도와 FPS
- 지킬 것: 비트 고정 컷, 코드 합성 음원, 음원 포함 MP4. 음성 검수는 `delivery.md`의 음성 기술·청취 항목을 따른다.

### 9. 픽셀 아트 캐릭터 액션 루프

외부 자산 없이 Canvas 2D로 그리는 16비트풍 캐릭터 루프다.
- 렌더링: 고정 논리 해상도 오프스크린 캔버스에 그리고, 화면에 맞는 최대 정수배로 확대한다(스무딩 끔). 모든 좌표는 정수로 스냅하고, 서브픽셀·안티앨리어싱·그라데이션·그림자 블러를 쓰지 않는다. 고정 팔레트 약 24색.
- 캐릭터: 사각형과 픽셀 런으로 절차적으로 그린다. 포즈 파라미터는 부드럽게 보간하되 매 프레임 그리드에 양자화해 8~12fps 도트 애니메이션 느낌을 낸다.
- 동작: 상태 기계(대기 → 충전 → 시전 → 회복), 미리 할당해 재사용하는 파티클(수명에 따라 팔레트 인덱스가 단계적으로 바뀜), 1~2px 화면 흔들림, 보석에서 오는 1px 림 라이트
- 품질 기준: 어느 크기에서도 선명한 픽셀, 끊김 없는 루프, 읽히는 실루엣. 축소한 벡터처럼 보이면 안 된다.
- 바꿀 것: 캐릭터, 동작 상태, 팔레트 분위기, 논리 해상도
- 지킬 것: 정수 스냅, 파라미터 포즈, 상태 기계, 풀링 파티클, 품질 기준. 영상으로 낼 때는 공통 규약의 고정 스텝 `seek(t)`로 바꾼다.

### 10. 픽셀 러너 회피 데모

#9의 렌더링 규칙 위에 횡스크롤 러너를 올린다. 캐릭터가 물결치는 무지개 바닥을 달리며, 정해진 공격 패턴(운석·예고선이 있는 빔·바닥 틈)을 아슬아슬하게 피한다.
- 회피: 점프, 2단 점프, 슬라이딩, 잔상 대시. 패턴마다 가장 멋있어 보이는 회피를 배정한다.
- 상태 기계: 달리기 → 예고 → 회피 → 니어미스 연출 → 달리기. 끝에서 가속과 워프 플래시를 거쳐 처음으로 자연스럽게 잇는다.
- 카메라: 정수 오프셋만 쓴다(줌·회전 없음). 감쇠 추종, 속도에 따른 앞당김, 니어미스 때 3~4프레임 히트스톱 후 짧은 슬로모션, 패턴 배열에서 읽는 흔들림
- 속도감: 3겹 패럴랙스(먼 별, 늘어나는 중경 별, 근경 스피드 라인), 큰 행성 배경, 모든 불꽃·꼬리·잔상을 하나의 파티클 시스템으로 처리
- 바꿀 것: 캐릭터 실루엣, 색, 공격 패턴 목록, 트랙 모티프
- 지킬 것: 고정 논리 해상도, 결정적 패턴 루프, 상태 기계, 카메라 규칙, 파티클 시스템, 품질 기준(빠름·아슬아슬함·멋짐이 매 회피에서 보일 것)

### 11. 타일 군집 제너러티브 필름

WebGL2와 순수 JavaScript로 만드는 단일 HTML 제너러티브 필름이다. 라이브러리·이미지·글꼴·오디오 파일은 쓰지 않는다. 재료 은유(원작은 유리와 금박 모자이크)의 타일이 고정되지 않아 들리고, 뒤집히고, 날았다가 제자리에 맞물린다. 형상은 타일의 군집으로만 표현한다. 물고기는 타일들이 헤엄쳐서 물고기가 된다.
- 이슈에 실린 원문은 앞부분만 있다. 장면 구성이 필요하면 원본 게시물을 확인하거나 사용자와 정한다.
- 바꿀 것: 재료 은유, 형상, 길이와 비율
- 지킬 것: 단일 파일, 라이브러리·자산 없음, "형상은 타일의 군집" 아이디어. 캔버스는 `seek(t)`가 시간으로 그린 뒤 렌더한다(`preserveDrawingBuffer: true`).

### 12. 사물 분해 해설 영상

제품 하나를 부품 단위로 분해하며 구조·수치·역사를 설명하는 장편 해설 영상이다. 연출·과학 해설·데이터 시각화·음악·산업 디자인·코미디 감각을 한 사람에게 모두 요구하는 역할 묶음으로 수준을 정한다. 스타일은 목록(콜라주, 아이소메트릭 2.5D, 플랫 벡터, 라인 애니메이션, 모핑, HUD, 글래스모피즘, 바우하우스 구성, 픽셀 등)에서 섞어 고른다.
- 현지화: 화면에 박힌 글자를 최소로 하고 내레이션만 바꾸면 다른 언어로 낼 수 있게 만든다. 자막은 두 언어로 단다.
- 순서: 조회수 목표·제품 유입·사업 모델까지 생각한 기획을 먼저 보여 주고, 사용자가 확정한 뒤 제작한다.
- 주의: 원문의 "여기서 어울리는 스타일을 보라"는 게시물에 없는 외부 자료를 가리킬 수 있다. 확인할 수 없으면 목록에서 고른다. 3분이 넘으므로 장(chapter) 단위 HTML로 나눠 렌더하고 이어 붙인다. 내레이션 음성과 자막의 권리·검수는 `delivery.md`의 음성 항목을 따른다.
- 바꿀 것: 분해할 대상, 길이, 내레이션 언어와 자막 쌍, 스타일 조합
- 지킬 것: 분해 해설 구성, 역할 묶음 수준, 내레이션 교체만으로 현지화, 기획 확정 뒤 제작

### 13. 캐릭터 하나의 다섯 세계 여정

단순한 마스코트(둥근 정육면체에 점 눈 두 개 같은 형태) 하나가 다섯 세계(바다, 도시, 우주, 숲, 네온)를 지나며 각 세계에 맞게 모습을 바꾼다. 전환은 모두 비트 위의 매치컷 모핑이다. 전부 코드로 처음부터 만든다.
- 채울 것: 원문에는 캔버스 규격·비트 맵·검증이 없다. 고정 BPM 비트 그리드를 정하고 세계마다 같은 길이의 구간을 배정한 뒤 공통 규약의 사전 점검을 적용한다.
- 바꿀 것: 제목, 마스코트(형태·색·눈), 다섯 세계, 길이
- 지킬 것: 코드로만 제작, 모든 장면에 같은 캐릭터 하나, 비트에 맞춘 매치컷 모핑

### 14. 스위스 에디토리얼 디더링 쇼릴

#0의 "꿈의 직장에 보낼 쇼릴" 브리프에 시각 스타일 목록 한 문단을 고정한다. 직함은 화면에 쓰지 않는다. 스타일은 네오브루탈리즘 스위스 에디토리얼, 흰 바탕과 은은한 사이키델릭 그라데이션 디더링, 촘촘한 1비트 디더링과 규칙적 픽셀 노이즈, 보이는 모듈 그리드, 아주 굵은 대형 네오그로테스크 글자, 모노 메타데이터, 고대비 미니멀 배치, Y2K 인터페이스 감성이다.
- 소리: 합성음 금지. 자연스러운 실제 효과음만 쓴다. 효과음은 사용자가 제공했거나 사용 허락된 로컬 파일이어야 하며, 없으면 만들지 말고 요청한다.
- 채울 것: 원문에는 비트 그리드·장 목록·검증이 없다. 둘 다 정하고 장 단위 HTML로 나눠 렌더한다.
- 바꿀 것: 스타일 문단(시각 특성의 촘촘한 목록 형태 유지), 길이, 출력 규격
- 지킬 것: 직함 없이 실력을 보여 주는 쇼릴 구도, 실제 효과음만, 감정을 움직이는 완성도 기준

### 15. 리퀴드 크롬 쇼릴

#14와 같은 구도에 다른 스타일 문단을 고정한다. 액체 크롬·수은 표면, 검은 바탕 위 무지갯빛 기름막 반사, 부풀린 3D 블롭 글자, 와이어프레임 홀로그램 UI, 아주 가는 모노 HUD, 커스틱 굴절광, 제품 렌더식 고광택 조명, 넓은 여백이다. 효과음은 원천을 구체적으로 지정한다(물·수은 방울, 유리 공명, 금속 그릇 타격, 느린 숨, 천 소리).
- HDR: 원문은 10비트 HDR HEVC(Rec.2020)를 요구한다. `render.mjs`의 기본 출력은 SDR이다. 사용자가 HDR을 확정하면 별도 FFmpeg 인코드 단계로 만들고, HDR 표시 장치에서 확인했는지 인계에 적는다. 그렇지 않으면 1080p H.264로 낸다.
- 기법: 크롬·커스틱은 그라데이션 겹침, 블러, 블렌드 모드 또는 WebGL 레이어로 흉내 낸다.
- 바꿀 것: 스타일 문단(표면·글자·HUD·조명·색 보정), 효과음 목록, 길이, 출력 규격
- 지킬 것: #14의 구도와 실제 효과음 규칙, 구체적인 음원 지정, HDR 보정 의도(SDR이면 밝은 하이라이트와 깊은 검정으로 대신)

### 16. 기능 타일 마이크로 애니메이션

제품 사이트의 기능 그리드(벤토) 타일마다 기능을 보여 주는 작은 장면을 넣는다. 원작은 영상이 아니라 실제 웹사이트 구현이다. 사이트에 넣는 작업이면 `fullops-frontend`로 넘기고 이 템플릿은 구조 참고로만 쓴다.
- 시작 전: 프로젝트의 기술 스택을 읽고 그 방식으로 만든다. 프로젝트에 없는 애니메이션 라이브러리는 추가하지 않는다. 재질(원작 재질 값 그대로 / 제품 디자인 토큰 / 둘을 섞음)과 애니메이션할 기능 3~5개를 사용자에게 먼저 고르게 한다.
- 재질 원칙: 차분한 중성색, 테두리 대신 1px 헤어라인, 따뜻한 색조의 옅은 그림자, 그라데이션 없음, 강조색은 결과에만 하나. 바깥·안쪽 모서리 반경은 동심을 유지한다. 장면 안은 추상 와이어프레임(글자 대신 막대)만 쓴다.
- 장면: 타일마다 아이디어 하나, "동작 → 결과" 2~4동작, 동작당 250~600ms, 전체 약 3초. 이동은 ease-out, 등장은 약한 스프링을 쓴다.
- 재생: 정지 상태가 마지막 프레임이다. 화면에 약 70% 보이면 잠깐 뒤 한 번 재생하고, 함께 들어온 타일은 읽는 순서로 시차를 둔다. 마우스 hover·키보드 focus 때 블러 속에서 다시 재생한다. 터치는 hover에 의존하지 않는다. 동작 줄이기 설정이면 마지막 프레임만 보인다.
- 색과 접근성: 모든 색은 변수로 두고 라이트·다크와 프로젝트 테마 전환을 따른다. 장식이므로 `aria-hidden`으로 두고 번역할 글자를 넣지 않는다. 실제 브라우저에서 첫 재생, 재재생, focus, 동작 줄이기, 다크 모드, 휴대폰 폭을 확인한다.
- 영상으로 낼 때: 그리드를 한 화면에 배치하고 IntersectionObserver 대신 `seek(t)` 타임라인에 타일별 시차 재생과 hover 재재생 비트를 넣는다.
- 바꿀 것: 기능 목록, 재질, 강조색, 타일별 장면
- 지킬 것: 타일당 아이디어 하나와 시간 예산, 이징, 정지 상태 = 마지막 프레임, 재생·재재생·동작 줄이기·다크 모드 규칙, 실제 브라우저 확인, 착수 전 재질과 기능 선택

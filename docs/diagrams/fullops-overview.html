FullOps Squad 0.6.0 · 플러그인 개요

누가 작업해도 같은 품질과 같은 산출물

FullOps Squad의 목표는 세 가지입니다. 모든 작업이 같은 검사 관문을 통과해 품질이 일정하고, 작업마다 지시서·검증 결과·리뷰·산출물이 레포에 남으며, 비싼 모델은 설계가 필요할 때만 써서 비용을 줄입니다. 모든 세션은 필수 IDE인 Orca 안에서 돌아갑니다.

01 · 품질과 산출물

작업 하나가 통과하는 관문과 남기는 기록

어떤 모델이 작업하든 같은 지시서 형식, 같은 lint 관문, 같은 리뷰 기준을 거칩니다. 단계마다 결과가 파일로 남아 나중에 누가 봐도 무엇을 왜 바꿨는지 추적할 수 있습니다.

02 · 역할 구조

누가 무엇을 맡는가

요청은 모두 coordinator로 들어옵니다. worker 구성은 레포마다 다르며 setup할 때 레포를 보고 정합니다. 아래 역할 이름은 예시입니다. architecture는 설계가 필요할 때만 띄우는 역할이라 점선으로 표시했습니다.

03 · 요청 라우팅

요청 하나가 병합되기까지

coordinator는 Jev의 확률을 보고 한 번만 판단합니다. 확신이 낮거나 호출이 실패하면 항상 설계 쪽으로 보냅니다.

04 · 질문 전달

worker가 판단을 요청할 때

worker는 짐작하지 않고 ask로 묻습니다. 형제 worker에게 직접 보내지 않고 항상 coordinator를 거칩니다.

05 · flow-gate 규칙

hook이 막는 시점

규칙을 말로 부탁하지 않고, 행동 직전과 종료 직전에 hook이 검사합니다. Claude Code, Codex, grok build에서 같은 스크립트가 동작합니다.

hook이 강제하는 것

  • worker는 worker-start --run으로만 띄운다
  • 배정 전에 jev_route.py 분류 기록이 있어야 한다
  • 설계 역할은 코드를 고치지 않는다
  • worker는 worker_done을 보내고 끝낸다

사람이 정해 둘 것

  • Orca IDE 설치 (필수)
  • setup에서 레포에 맞는 worker 역할 확정
  • orca-agents.md에 라우팅 기준과 역할별 모델 배정
  • coordinator는 기본 브랜치에서 저렴한 모델로 연다

매 작업 남는 기록

  • 지시서와 완료 보고 전문
  • lint 결과와 리뷰 보고서
  • 산출물 D01–D13 원천 갱신

# FullOps Squad 0.7.0 변경안

## 범위

사람이 프로젝트 진행을 눈으로 확인하는 작업 현황판을 추가한다. 산출물 문서에 메타정보(front matter)를 두고, 이 메타정보를 스크립트로만 쓰고 lint로 검사해 모델 성능과 상관없이 형식이 같게 한다. Jev가 요청마다 갱신할 산출물도 고른다.

## 작업 현황판

- `.fullops-squad/board/index.html`은 플러그인이 제공하는 고정 양식이다. 브라우저로 열면 60초마다 새로고침하고, 화이트·블랙 테마를 전환할 수 있다.
- coordinator는 `board/board.json`에 제목·요약·프로젝트 단계(done/active/blocked/todo)와 단계별 산출물 ID만 쓴다.
- `scripts/board.py`가 나머지를 레포 기록에서 모아 `board/board-data.js`를 만든다. 역할별 인박스, `PLANS.md`(여러 표·섹션, 맨 위 요약 문단), 작업 로그, Jev route, 리뷰 결과와 lint ERROR·WARNING, 산출물 상태와 front matter를 읽는다.
- coordinator 세션이 끝날 때 flow-gate Stop hook이 자동으로 다시 만든다. 내용이 바뀌었을 때만 쓰고 worker 브랜치에서는 실행하지 않는다. `board-data.js`는 `board/.gitignore`로 커밋하지 않는다.

## 산출물 front matter

- 원천 문서 맨 위에 `id`·`title`·`status`·`updated`·`owner`·`tasks`·`upstream`·`downstream`·`summary`를 둔다. 원천이 여러 파일이거나 폴더면 각 문서에 같은 `id`를 적는다.
- `deliverables.py --stamp`로만 쓴다. 필드 순서와 목록 표기를 고정하고, `updated`를 오늘 날짜로, 과제 키를 `tasks`에 더하고, 인덱스 표의 상태를 같은 값으로 맞춘다.
- lint `DOC-002`(ERROR): 바뀐 원천 문서의 front matter가 없거나, 필수 필드·id·상태·날짜가 틀리거나, 인덱스와 상태가 다르거나, `--stamp` 출력과 글자 그대로 같지 않으면 막는다. worker 종료(done-gate)와 병합 전 리뷰가 lint 통과를 요구하므로 손으로 쓴 형식은 여기서 걸린다.
- `deliverables.py --strict`는 전체 원천 문서의 front matter 문제를 오류로 본다. 기본 실행은 경고만 낸다.
- 현황판은 front matter를 인덱스 표보다 우선해서 읽고 갱신일·담당을 보여 준다.

## Jev 산출물 라우팅

- `jev_route.py`가 같은 호출에서 이 요청으로 갱신할 산출물(D01–D13)을 고른다. 선택지 설명은 인덱스와 front matter의 `title`·`summary`이고, 범위 밖 산출물은 빼고 "해당 없음"을 둔다.
- 개별 확률 0.2 이상, 누적 0.8까지, 최대 3개를 고른다. 산출물 답이 이상해도 역할 라우팅은 유지한다. 결과는 route.json의 `deliverables`에 남는다.
- 지시서 템플릿에 `## 갱신할 산출물`을 추가했다. coordinator·설계 역할이 route 결과를 옮기고, worker가 해당 문서를 갱신한 뒤 `--stamp`로 front matter를 쓴다.

## 기타

- lint 기본 제외에 `.fullops-squad/board/**`를 추가했다.
- `lint.py --out`을 UTF-8로 쓴다. 전에는 Windows에서 한글이 깨질 수 있었다.
- `deliverables.py`가 파일을 UTF-8로 읽는다.

## 기존 레포 적용

README의 "시작 프롬프트 → 기존 레포 0.7.0 업데이트"를 서비스 레포 기본 브랜치의 coordinator 세션에 붙여 넣는다. 플러그인 갱신도 이 세션에서 한다. 실행 중인 세션은 옛 스킬·hook을 쓰므로 갱신 뒤 스크립트는 새 플러그인 경로에서 실행한다. setup은 새 파일(`board/`)만 추가하고 기존 문서는 바꾸지 않으므로 아래는 직접 반영한다.

1. 플러그인 체크아웃을 최신으로 맞추고 설치기로 0.7.0을 설치한다. grok은 버전이 그대로면 제거 후 다시 설치한다.
2. setup을 기존 역할로 다시 실행해 `board/`를 추가한다.
3. `handovers/_TEMPLATE.md`에 `## 갱신할 산출물` 절을, `lint/lint.json`의 `exclude`에 `.fullops-squad/board/**`를, `FULLOPS.md` 표에 현황판 행을 더한다. `docs/deliverables/README.md`의 front matter 절은 플러그인 템플릿에서 옮긴다.
4. `board/board.json`에 실제 단계와 산출물 연결을 쓴다.
5. `deliverables.py --strict`의 경고가 없어질 때까지 원천 문서마다 `--stamp`를 실행한다. 하지 않으면 그 문서를 고치는 worker가 `DOC-002`로 막힌다.
6. 기본 브랜치에 커밋하고, 쉬고 있는 역할 브랜치에 반영한다.
7. 새 hook은 새 세션부터 적용된다. 다른 PC와 worker 세션도 플러그인을 갱신하고 새 세션을 연다.

## 검증과 한계

`npm test`에 `tests/board.py`와 `tests/deliverables.py`를 추가하고 `tests/jev-route.py`에 산출물 라우팅 사례를 더했다. Windows 로컬에서 `npm test`와 `npm run test:review`가 통과했다. 실제 사용 레포(erden-unity) 기록으로 현황판 수집을 읽기 전용으로 확인했다.

실제 Jev의 산출물 선택 정확도와 기준값(0.2·0.8)은 측정하지 않았다. front matter 파서는 `키: 값`과 `[a, b]` 목록만 지원한다. 현황판은 브라우저가 로컬 파일의 스크립트를 읽을 수 있어야 하며, 데이터는 coordinator 세션 종료나 수동 실행 때 갱신된다.

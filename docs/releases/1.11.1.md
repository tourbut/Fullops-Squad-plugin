# 1.11.1 — 이슈 자동 모드 실환경 검증에서 막힌 6건

근거: 이 레포에서 이슈 #109를 자동 모드로 끝까지 처리했다(draft PR #110). coor와 worker는 우회 없이 정상 경로로 진행했지만, 아래 지점에서 막혔고 그중 push 차단은 시도 하나를 소모했다. 기록은 `docs/issue-auto-mode.md` "수용 검증 결과"에 있다.

## 변경

- **`2>&1` 파싱**: 셸 명령 분해가 `2>&1`의 `&`를 명령 구분자로 잘라 worker의 정확한 `git push origin HEAD:refs/heads/fullops/issue-…`가 금지 push로 판정됐다. fd 복제 리다이렉트는 분석에서 뺀다. 공용 gate 파서라 다른 명령 판정에도 적용된다.
- **설치된 플러그인 스크립트 실행**: `~/.claude/plugins/cache/…/work.py`처럼 플러그인 캐시의 스크립트를 인터프리터로 실행하면 host 파일 변경으로 막혔다. 실행은 허용하고, 같은 경로를 쓰거나 다른 host 파일을 인자로 넘기는 명령은 계속 막는다.
- **`git switch -c`**: 설정 주입(`git -c key=val`) 검사가 subcommand 뒤의 `-c`까지 잡았다. `-c`·`-C`는 subcommand 앞 전역 옵션에서만 본다.
- **여러 문장의 제어 명령**: PowerShell에서 변수 대입과 함께 쓴 `issue_mode.py … --token-file <lease>`가 비밀정보 규칙에 걸렸다. coor의 제어 명령은 통과시키고 같은 줄의 다른 명령만 검사한다.
- **coor lease를 worker 워크트리에 링크하지 않음**: `.fullops-squad/.env*` 링크가 coor의 lease 파일까지 worker 체크아웃에 넘겼다. lease JSON은 링크에서 뺀다.
- **`wait --ack`**: `orchestration_actionable`을 처리한 뒤 Orca에 직접 ack해야 했다. 다음 `wait --ack <deliveryId>`로 넘긴다.
- **`answers` 결과와 순서**: 성공해도 `null`을 출력했고, `sync`를 먼저 실행하면 받은 답변을 판단할 수 없었다. 결과 상태를 출력하고, 오류 메시지와 스킬에 `answers`를 먼저 실행하라고 적었다.
- **스킬**: 이슈 브랜치 워크트리는 `git worktree add <경로> fullops/issue-<번호>-a<시도>`로 만들고 `worker-start --worktree path:<경로>`로 배정한다(Orca `worktree create`는 다른 브랜치 이름을 만든다).

## 남은 것

- 세션 종료·lease 만료·새 coor 인계(수용 기준 3)와 busy 중 수집·비허용 작성자(기준 2 일부)는 아직 실환경에서 시험하지 않았다.
- `jev_packet.py`가 이 레포에서 300초를 넘었다.

## 기존 레포 적용

플러그인 업데이트 후 coor 세션을 새로 시작하고 자동 모드를 다시 enable한다. 워크트리에 이미 링크된 lease 파일(`.fullops-squad/.env.issue-mode-lease.json` 등)은 지운다.

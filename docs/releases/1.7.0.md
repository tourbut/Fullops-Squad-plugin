# 1.7.0 — 사용자 결정 기록, 템플릿 기반 모션 제작

## 변경

- **사용자 결정 기록**: coordinator가 사용자에게 물은 결정을 기록해 둔다. 여러 결정을 물었는데 하나만 답을 받고 진행하다 나머지를 잊는 문제를 막는다.
  - 새 스크립트 `scripts/decision.py`(`add`·`answer`·`drop`·`list`)가 결정을 Git 공용 디렉터리 `fullops-decisions/`에 저장한다. 모든 워크트리가 같은 기록을 본다.
  - coordinator·주 담당 세션이 시작되면 열린 결정 목록이 세션 문맥에 들어간다. 새 세션을 열어도 이어서 묻는다.
  - `fullops-orca` 규칙이 추가됐다. 결정을 물을 때 항목마다 기록하고, 답을 받으면 닫는다. 일부만 답을 받으면 남은 결정을 다시 나열한다. 열린 결정에 걸린 작업은 추정으로 진행하지 않는다.
- **fullops-meter 0.7.0**: `/fullops` 패널을 위아래로 나눴다. 위는 기존 Workers/Reviews이고, 아래는 답을 기다리는 결정 목록(id·과제 키·경과 시간·질문·선택지·막힌 작업)이다. Claude Code 마켓플레이스에서 별도로 업데이트한다.
- **모션 제작 기본 경로 변경(동작 변경)**: `fullops-motion`의 기본 경로는 이제 템플릿 → 단일 HTML → 로컬 렌더 순서다.
  - `templates.md`: 공개 모션 프롬프트 12개의 구조를 다시 쓴 템플릿을 담았다. 원문은 싣지 않고 제작자와 원본 링크만 남긴다. `seek(t)`, 닫힌 형식 스프링, 루프 일치, 스틸 사전 점검 같은 공통 규약도 정리했다.
  - `render.mjs`: `window.seek(t)`를 가진 HTML을 Playwright로 프레임마다 캡처해 FFmpeg로 MP4를 만든다. 서브프레임 모션 블러, 스틸 추출, 음원 믹스를 지원한다.
  - HyperFrames·Remotion은 사용자가 지정했거나 기존 프로젝트가 쓰거나, 긴 내레이션·여러 장면 합성이 필요할 때만 쓴다.
- **소개 영상**: 이 경로로 만든 15초 레포 소개 영상과 소스를 `docs/intro/`에 넣었다.

## 기존 레포 적용

1. 플러그인을 업데이트한 뒤 새 설치 패키지의 `scripts/deps.py --host <현재 CLI>`와 `--check --host <현재 CLI>`를 실행한다.
2. 레포 파일 변경은 없다. 결정 기록 폴더는 처음 기록할 때 Git 공용 디렉터리에 생긴다(레포 작업 트리에는 생기지 않는다).
3. 패널의 결정 목록을 보려면 Claude Code에서 `fullops-meter`를 0.7.0으로 업데이트한다.
4. 기본 경로로 모션을 렌더하려면 영상 폴더에 `playwright`(또는 `playwright-core`와 시스템 Chrome)와 FFmpeg가 필요하다. 공통 설치에는 넣지 않았다.

## 검증과 한계

- 로컬 `npm test`가 통과했다. `tests/decision.py`가 번호 부여·워크트리 간 공유·닫기·잘못된 입력을 확인한다. `tests/flow-gate.py`는 열린 결정이 시작 문맥에 들어가는지 확인한다. fullops-meter 테스트 65개와 타입 검사도 통과했다.
- `render.mjs`는 Windows 11, Node 24, playwright-core 1.49.1과 Chrome, FFmpeg 8.0.1에서 실제로 렌더해 확인했다. 소개 영상은 1920×1080, 60fps, 900프레임이다. macOS와 Linux에서는 실행하지 않았다.
- 결정 기록은 coordinator가 규칙을 지키는 데 달려 있다. 기록 없이 채팅으로만 물은 결정은 남지 않는다.
- 나뉜 패널을 실제 coordinator 세션에서 눈으로 확인하지 않았다.

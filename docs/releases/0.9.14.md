# FullOps Squad 0.9.14

배포 승인 근거: 2026-10-06 사용자의 수정본 배포 및 로컬 Codex·Claude Code·Grok 플러그인 업데이트 요청.

## 변경

- 이슈 #2: 기존 Jev 결과를 보존하고 호출을 생략했을 때 실패로 오해할 수 있는 안내를 수정한다. force 재선정·입력 검증·UTF-8 동작은 유지한다.
- 이슈 #3: 기존 테스트 명령의 kind·종료코드 증거, 변경 추가 줄 예산 SIZE-002, 의존성 선언 변경 DEP-001과 기본 SLOP WARNING을 보강한다. 기존 기준의 merge-base 고정과 실패 차단을 유지한다.
- 이슈 #4: 보드에서 연결된 원천 문서를 읽는 뷰어를 제공한다. 여러 문서·누락 상태·키보드 복귀와 읽는 동안 자동 새로고침 유예를 지원한다. 원천·상태는 보존하고 기본 Markdown은 HTML을 escape해 표시한다.
- 이슈 #5: 디자인 lint 명령 연결과 shadcn 플러그인 설정 안내, DESIGN-001–003 WARNING, 토큰·공용 컴포넌트·테마 전환에 대한 UI 핸드오버·리뷰 기준을 추가한다. 규칙별 exclude_paths는 해당 규칙에만 적용한다.
- 새 setup 설정에 루트 package.json의 기존 lint(없으면 lint:design)·typecheck·test 스크립트를 패키지 매니저에 맞춰 등록한다. 기존 lint.json은 보존한다. setup 스킬은 실제 레포의 스택·설정·모노레포 범위를 확인해 필요한 lint 설정·개발 의존성을 구성하고 실행 결과까지 확인한다.
- 공통 규칙 식별자는 fullops-common-0.3.3이다. shadcn은 Tailwind v4 서비스의 개발 의존성으로만 구성하며 FullOps의 필수 설치 목록에는 넣지 않는다. 영상 제작 도구는 범위에서 제외한다.

## 기존 레포 적용

1. 글로벌 플러그인을 업데이트하고 새 세션을 연다. 진행 중 worker·지시서·완료 기록과 사용자 설정을 보존한다.
2. 기존 역할로 setup을 dry-run한 뒤 실행한다. 기존 lint.json·문서는 자동 교체되지 않으므로 새 템플릿과 비교해 필요한 절만 통합한다. 린터·포매터·타입 검사·테스트를 실제 명령과 cwd로 연결하고 같은 HEAD의 실행 결과를 남긴다.
3. 기존 rules를 보존하며 필요한 SLOP·DESIGN 항목과 SIZE-002 예산을 명시적으로 추가한다. DESIGN은 WARNING부터 적용하고 토큰 정의·브랜드 원본 예외는 개별 규칙의 exclude_paths에 좁게 지정한다. 설정 변경은 merge-base 정책에 따라 먼저 병합한 뒤 후속 작업에 적용한다.
4. Tailwind v4 UI가 있으면 lint/README.md의 shadcn 절을 따른다. 기존 ESLint/Oxlint 설정과 검사 수준을 보존한다. Vue·Svelte 템플릿은 해당 parser가 있는 ESLint로 검사한다. 다른 스택은 그 스택의 기존 또는 적합한 도구로 구성한다.
5. 공통 코딩 기준·README·project.md의 규칙 식별자, 핸드오버 UI 검사 항목, 리뷰 템플릿과 lint 안내의 필요한 절을 통합한다. UI가 없는 레포는 디자인 도구를 설치할 필요가 없다. 미작성·미실행 항목은 이유와 남은 검증을 기록한다.
6. 보드 HTML은 신규 뷰어로 갱신하고 board.py로 데이터를 다시 만든다. 기존 title·단계·산출물 연결과 원천 문서는 보존한다.

## 검증과 한계

기본 회귀는 npm test, 실제 OCR delegate 검사는 tests/review-check.py, shadcn 연계는 tests/shadcn-lint.py로 검증한다. shadcn 샘플은 실제 @shadcn/lint 0.2.0·ESLint 9.33.0·parser 8.40.0·Tailwind 4.3.3으로 위반 종료코드 1과 정상 종료코드 0·HEAD 게이트를 확인한다. 이 버전은 재현용이며 서비스는 호환되는 지원 버전을 선택한다. 보드 뷰어는 file://·HTTP·키보드·모바일과 새로고침 동작을 실제 Chrome에서 확인한다.

DESIGN은 정규식 휴리스틱이며 실제 테마·컴포넌트 계약을 추론하지 않는다. 내용·경로 예외와 정상 동적 스타일의 오탐을 검토자가 판단한다. UI 핸드오버의 서술은 review.py check가 자동 판정하지 않는다. 실제 서비스의 테마 전환·접근성·전체 화면 품질은 해당 레포에서 검증한다.

npm 설치기는 구현 변경이 없어 0.9.11을 유지하며 최신 GitHub 플러그인을 받는다.

# 1.8.3 — 가벼운 QA와 현황판 가독성

## 변경

### QA 부담 줄이기 (fullops-common-0.3.5)

KnowsLink(test_level lite)와 jevpet(minimal)에서 1.8.0 뒤에도 QA 보고가 구현보다 큰 몫을 차지했다. 지시서가 레벨과 무관하게 3폭·라이트/다크 캡처와 tester·designer 검수 차수를 붙였고, 수정·재검증·후속마다 새 보고서 폴더가 생겼다(KnowsLink 과제 하나에 보고서 9개, jevpet DEV 캡처 36장 중 보고서 링크 7장).

- **레벨별 검수 범위**: `minimal`은 별도 tester·designer 검수 차수를 만들지 않는다. `lite`는 새 화면·새 사용자 흐름·통합 후보에서만 tester 독립 QA와 designer 시각 검수를 배정한다. `standard`부터 바뀐 사용자 흐름을 tester가 독립 QA한다. 보안·데이터 손실 방지·필수 검사·독립 코드 리뷰·최종 수락 조건은 그대로다.
- **개발 과제 검증**: minimal·lite 개발 과제는 lint와 변경 동작 테스트로 검증한다. UI 과제는 디자인 정본과 비교하며 고치는 작업용 캡처만 쓰고 증거로 커밋·보고하지 않는다. 과제마다 보고용 캡처를 늘려도 완성도가 오르지 않았다.
- **큰 틀 검수**: 주요 사용자 흐름은 고정 시나리오 세트로 유지해 통합 후보마다 다시 돌리고, 발견한 결함은 시나리오로 추가한다. UI/UX 품질은 통합 후보·마일스톤에서 그 흐름을 처음부터 끝까지 실행해 화면 사이의 흐름·일관성·정보 구조를 함께 본다. 결과는 우선순위를 매긴 개선 목록 하나이고, 다음 개선 과제는 그 목록을 범위로 여러 화면을 함께 바꾼다. 캡처는 이 검수에서 판정에 쓴 화면만 남긴다.
- **지시서**: 레벨 밖의 검사·캡처 폭·테마·검수 역할을 더하지 않는다. 더 필요하면 레벨을 올리거나 사용자에게 묻는다. 개선은 사용자 흐름 단위 계획에서 시작하고 과제는 그 계획을 리뷰 가능한 PR 크기로 나눈다. 같은 단위의 작은 후속 여러 건은 한 과제로 묶는다.
- **보고서**: 같은 과제의 수정·재검증·배포 확인은 새 폴더 대신 기존 `report.md`에 절을 덧붙인다. 판정 표와 실패·미실행·한계만 적고 minimal·lite는 30줄 안팎이다. 증거용 일회성 스크립트와 출력은 `raw/`에 둔다.
- **낮은 심각도 지적**: 수락을 막지 않으면 PLANS.md 후속으로 남기고 별도 수정·재검증 차수를 열지 않는다.

방향은 [AI-native SDLC 플레이북](https://claude.com/ko/resources/articles/the-ai-native-sdlc-playbook)의 자체 검증 루프·지속 평가와 맞췄다(#82). 기계적 강제(lint·gate)는 넣지 않았다. 규칙·스킬·지시서 템플릿 문장만 바꿨다.

### 현황판

- **확인 필요 줄**: 머리말 아래에 막힌 단계·막힌 과제·실패한 테스트·차단 지적이 있는 리뷰 수를 한 줄로 모아 보여 준다. 해당 항목이 없으면 줄이 나오지 않는다.
- **상태 색 분리**: 막힘·실패·차단은 진행 중(주황)과 다른 위험 색으로 표시하고, 막힌 단계·과제 카드는 테두리도 같은 색이다. 점 모양(채움·빈 원)과 글자 라벨은 그대로라 색만으로 구분하지 않는다.
- **대비**: 보조 글자·주황 글자·다크 테마 링크를 본문 배경 대비 4.5:1 이상으로 올렸다. 표 머리글은 10px에서 11px로 키웠다.
- **좁은 화면**: 560px 이하에서 단계 카드를 두 열로 두고 높이를 내용에 맞춘다. 표는 단어를 쪼개지 않고 가로로 스크롤한다. 머리말의 저장소 정보는 왼쪽 정렬한다.
- 넓은 화면에서 단계 카드 여섯 개가 한 줄에 들어간다. 2단 영역(현재 작업·리뷰 결과, 최근 완료·산출물)은 두 칸의 아래 구분선 높이를 맞추고, 담당·lint 열이 줄바꿈되지 않게 열 폭을 고쳤다.

## 기존 레포 적용

- `rules/common/testing.md`를 0.3.5 판으로 바꾸고 `rules/common/README.md`·`project.md`의 규칙 묶음 표기를 `fullops-common-0.3.5`로 올린다. `handovers/_TEMPLATE.md`의 `완료 기준과 검증`·`UI 작업의 디자인 기준과 검증` 문장을 새 판으로 바꾼다. 진행 중 지시서는 다음 배정 때부터 새 범위로 쓴다.
- 현황판: 할 일 없음. `board/index.html`은 플러그인 소유 양식이라 coordinator 세션이 끝나 `board.py`가 현황판을 갱신할 때 새 양식으로 바뀐다. board.json과 함께 커밋한다.

# 1.19.0 — 리뷰 정책

#82 로드맵의 P3(리뷰 정책)를 반영했다. 기존 OCR 리뷰에 세 관점, 심각도 정의, nit 상한을 더했다. 코드 변경도 새 강제도 없고 문서와 시험만 바뀌었다. 아래의 플레이북은 [AI-native SDLC 플레이북](https://claude.com/ko/resources/articles/the-ai-native-sdlc-playbook)이다.

## 변경

- **`fullops-review` 스킬:** `## 리뷰 정책` 절을 추가했다.
  - 관점: 한 세션에서 버그·보안·준수로 읽는다. 관점마다 검토자를 따로 띄우지 않는다.
  - 태그: findings의 `content` 앞에 `[버그]`·`[보안]`·`[준수]` 또는 `[nit]`을 하나 붙인다.
  - 준수: 지시서의 완료 기준·`증명 방법`·`상위 의도`에서 맡은 성공 기준, 요구사항·설계 정본, UI 디자인 정본을 diff와 대조한다. 완료 보고와 검증 기록이 사실과 맞는지도 본다. 지시서가 없는 직접 작업은 과제의 완료 조건 기록을 대조한다.
  - 심각도: critical/high는 병합 전에 반드시 고쳐야 할 결함이다. medium은 실제 영향이 있지만 병합을 막을 정도는 아닌 결함이나 기준 미달이다. low는 조건이 드물거나 영향이 작은 결함과 개선 제안이다.
  - 미해결 medium: report.md의 `## 검토 결론`에 처분(병합 전 수정, 후속 과제 키, 사용자 결정)을 적는다.
  - 완료 기준 미달: medium 이상으로 적는다.
  - nit: 코드·절차·기록의 정확성에 영향이 없는 표기·명명·문구다. severity는 low로 적는다. 리뷰당 5건까지 적고 나머지는 report.md에 건수만 적는다. PLANS.md 후속으로 올리지 않는다. 다른 지적은 세지 않는다.
- **리뷰 보고서 템플릿(`review/_REPORT.md`):** 완료 기준 줄에 기준별 충족/미달을, 발견 사항에 태그를, 검토 결론에 미해결 medium의 처분을 추가했다.

## 알아 둘 점

- `review.py check`는 이 정책을 검사하지 않는다. severity 값 4개와 미해결 critical/high 차단은 그대로다. 태그와 처분은 문서 규약이다.
- 플레이북의 Important는 FullOps의 critical/high에 가장 가깝지만, 실제 영향이 있는 medium도 일부 포함한다. 플레이북의 지적은 그 자체로 병합을 차단하지 않고 차단은 선택 사항이다. FullOps의 `review.py check`는 미해결 critical/high에서 실패한다. 이 차이는 유지한다.
- high의 정의는 지금 쓰임을 옮긴 것이다. 차단 범위를 넓히지 않는다.
- 플레이북의 `REVIEW.md` 파일은 만들지 않는다. 이 스킬 절이 그 역할을 한다.
- 플레이북의 제외 항목 중 생성 경로는 기존 경로 제외(`review/rule.json`의 exclude, `review.py prepare`의 skipped 처리)로 대응한다. "CI가 이미 강제하는 항목"에 대응하는 제외 규칙은 없고 이번에도 추가하지 않았다.
- 5는 플레이북의 예시 값이다. 과거 리뷰 기록에서 nit이 5건을 넘은 리뷰는 찾지 못했다.
- 리뷰를 수행하지 않는 변경(`need`가 `skip`이고 별도 리뷰 요청이 없는 변경, 사용자가 waive한 변경)에는 적용되지 않는다. 범위 기준은 바꾸지 않았다.
- 이미 prepare한 리뷰의 report.md와 check 판정은 바뀌지 않는다.
- `fullops-meter`는 미해결 nit도 미해결 low로 표시한다. nit을 findings에 적으면 그 수가 보인다.

## 기존 설치 적용

- 플러그인을 1.19.0으로 갱신한 뒤 새 패키지의 `scripts/deps.py --host <현재 CLI>`를 실행한다. 이어서 `scripts/deps.py --check --host <현재 CLI>`로 확인한다. Claude Code는 사용자가 `/reload-plugins`를 실행한 뒤 같은 세션에서 이어간다. Codex·grok은 새 세션을 시작한다.

## 기존 레포 적용

필수 적용은 없다. `review.py prepare`는 설치된 패키지의 템플릿으로 보고서를 만든다.

- 레포의 `.fullops-squad/review/_REPORT.md` 사본은 어떤 스크립트도 읽지 않는다. 참고본으로 유지하는 레포만 설치된 패키지의 `assets/repository/.fullops-squad/review/_REPORT.md`와 비교해 바뀐 3곳을 병합한다. 그 밖에는 해당 없음으로 기록한다.

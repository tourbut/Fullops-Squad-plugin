# FullOps Squad 0.9.5

## 범위

정상 작업 중 coordinator의 로그 조회를 줄이고 운영 설정을 레포의 `.fullops-squad/.env`에서 관리한다.

## 변경

- 착수를 한 번 확인한 뒤 `worker_done`을 기다린다. 정상 작업의 추가 로그 확인은 worker별 설정 주기가 지난 뒤 필요한 최근 출력에 한정한다. 질문·오류·escalation과 사용자 진단 요청은 즉시 처리한다. task 목록은 배정·재개·완료 상태 파악에 사용한다.
- `FULLOPS_WORKER_CHECK_MINUTES`는 확인 주기(기본 60분), `FULLOPS_WORKER_READY_TIMEOUT_SECONDS`는 worker 시작 대기 시간(기본 90초), `FULLOPS_WORKER_LOG_LIMIT`은 로그 조회량 상한(기본 30개 메시지/줄)이다. 시작 대기와 로그 상한은 coordinator가 명령 옵션에 적용하는 운영 규칙이다.
- `orca_wait.py --repo <레포 루트> --settings`가 위 세 설정만 JSON으로 출력한다. API 키는 출력하지 않는다. 프로세스 환경 변수, 레포 `.env`, 기본값 순으로 사용하고 `--max-minutes`는 이번 대기의 확인 주기를 덮어쓴다. 설정 변경은 다음 조회·대기 실행부터 반영된다.
- heartbeat·status는 대기 스크립트가 흡수한다. 확인 주기 전에 `worker_done`·질문·escalation이 오면 즉시 반환한다. 잘못된 설정은 값 자체를 출력하지 않고 거부한다.
- setup에 `.fullops-squad/.env.example`을 추가했다. 기존 `.env`는 보존한다.

## 기존 레포 적용

플러그인 업데이트 뒤 새 coordinator 세션을 연다. setup을 갱신하면 없는 `.env.example`만 추가된다. 원본 체크아웃의 `.fullops-squad/.env`에 원하는 운영 설정을 추가하며 기존 API 키는 보존하고 파일은 커밋하지 않는다. 설정이 없어도 기본값으로 동작한다. 기존 워크트리 링크는 그대로 쓰며 복사 방식으로 연결된 워크트리는 별도로 값을 맞춘다. 진행 중 worker는 완료 보고와 결과를 보존한 뒤 새 세션으로 전환한다.

## 검증

`npm ci`, `npm test`, `git diff --check`를 확인했다. 가짜 Orca CLI로 완료 메시지의 즉시 반환, heartbeat 흡수, 설정 우선순위, 유효성 검사와 설정 조회의 비밀값 제외를 검증했다. 실제 worker 시작·로그 조회 옵션 적용은 coordinator 운영 규칙이며 별도 Orca 통합 검증 대상이다.

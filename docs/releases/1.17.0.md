# 1.17.0 — Stop 대기 완화, hook·lint 속도 개선, Orca `--full` 응답 대응

#112, #132의 선행 개선, PR #126에서 후속으로 남긴 항목을 처리했다(#134, #135). 가장 중요한 수정은 Orca 1.4.246 이상의 기본 응답 대응이다. 1.16.1은 Orca 목록과 Run 정보를 `--full` 없이 읽었다. 그래서 이 Orca에서 이슈 자동 모드를 켤 수 없었고, 리뷰어의 완료 보고를 병합 대상으로 기록했다.

## 변경

- **Claude Code Stop 대기(#112):**
  - worker가 실행 중이어도 이 Run의 `orca_wait.py`가 백그라운드로 실행 중이면 Stop을 막지 않는다. 대기 중에도 사용자 메시지를 받고 다른 역할을 배정할 수 있다.
  - 처리하지 않은 `worker_done`·질문·escalation이 있으면 대기가 있어도 막는다.
  - 대기가 없으면 한 번 막고 `orca_wait.py`를 `run_in_background`로 걸라고 안내한다.
  - 호스트는 Stop 입력의 snake_case `background_tasks`로 판별한다. Codex·grok은 이전처럼 포그라운드 대기를 안내한다.
- **Orca `--full` 응답:**
  - Orca 1.4.246 이상의 기본 응답에는 `run`·`spec`·`count`·`page`가 없다. 이슈 모드, 완료 기록, flow-gate가 목록과 Run 정보를 `--full`로 읽는다.
  - 이슈 자동 모드의 `enable`과 token을 쓰는 명령(`sync`·`reconcile`·`claim`·`wait` 등)이 다시 동작한다. 하위 Run 배정도 다시 동작한다.
  - 이슈 Run에 속한 worker는 task spec을 읽지 못하면 도구 호출이 거부된다. 1.16.1은 이 worker를 무관한 worker로 판정해 push·비밀 파일 검사를 건너뛰었다.
  - 리뷰어의 `worker_done`(spec의 `Purpose: review`)을 다시 병합 기록에서 뺀다. 이 수정은 이슈 모드가 아닌 일반 Orca 운영에도 적용된다.
  - flow-gate가 `worker-start --task <id>` 배정에서 저장된 task의 과제 키를 다시 읽는다.
- **이슈 모드 인계·잠금:**
  - 다른 host 세션의 coor로 인계되면, 새 lease가 유효한 동안 이전 coor의 외부 명령(worker 배정·push·`gh` 변경)을 막는다. 대상은 미종료 이슈의 과제 키나 이슈 브랜치 접두사를 담은 명령이다.
  - 질문을 게시하는 중에 lease를 잃어도 댓글 ID를 outbox에 남기고 `question_sent_after_fence` event를 기록한다. 작업 상태는 현재 소유자만 바꾼다.
  - `answers`와 `complete`는 GitHub 조회를 SQLite 쓰기 잠금 밖에서 하고, 잠금 안에서 다시 확인한다.
  - `reconcile --not-dispatched`가 시작되지 않은 dispatch intent를 닫는다. 마지막 intent 뒤 600초가 지나야 하고, 관련 Run의 전체 목록에 같은 과제 키의 task가 없어야 한다. 닫힌 이슈는 held가 되고, 새 attempt와 새 과제 키로 재시도한다.
  - 이슈와 무관한 worker는 도구 호출마다 Orca를 조회하지 않는다.
- **완료 기록(`integration.py`):**
  - 완료 기록을 원자적으로 쓴다. 동시에 도는 `orca_wait`가 빈 기록을 읽고 `JSONDecodeError`로 죽지 않는다. 이전 버전이 남긴 빈 기록은 다음 기록 때 다시 쓴다.
  - 새 명령 `integration.py set-sha --message <완료 메시지 ID> --sha <SHA> [--key <과제 키>]`는 본문에서 SHA를 읽지 못한 보고에 SHA를 기록한다. hold를 거치지 않는다. 저장소에 없는 커밋은 거부한다.
  - 인박스 작성과 `worker-start`를 한 명령으로 묶어 배정 검사가 실패하면, 실패 안내가 명령을 나누라고 알려 준다.
- **속도(#132 선행 개선):**
  - lint와 Stop의 done-gate는 파일 내용을 `git cat-file --batch -Z` 한 번으로 읽는다.
  - hook은 저장소 위치를 프로세스당 한 번만 묻는다. 자동 이슈 상태(`fullops-issues/state.sqlite`)가 없는 레포에서는 `issue_mode`를 불러오지 않는다.
  - Stop의 현황판 갱신은 성공한 `gh issue list` 결과를 5분 동안 다시 쓴다. `board.py`를 직접 실행하면 바로 조회한다.
  - Jev 검색 메타데이터를 `git cat-file --batch` 한 프로세스로 만든다. 검색 캐시에서 읽지 않는 필드를 지웠다(캐시 스키마 2).
- **lint:**
  - diff의 서브모듈 gitlink를 내용 검사에서 건너뛴다. 이전에는 lint가 종료코드 2로 멈췄다.
  - lint·시험 명령을 Windows는 Job Object, POSIX는 새 세션으로 실행한다. timeout과 Ctrl+C 중단 때 손자 프로세스까지 끝낸다. POSIX에서는 SIGTERM·SIGHUP도 중단으로 처리한다.
- **리뷰(`review.py`):**
  - 텍스트 증거와 `rule.json`의 해시를 LF로 정규화해 기록한다. 검증은 원본·LF·CRLF 중 하나가 맞으면 통과한다. 그래서 `core.autocrlf=true` 체크아웃도 유효한 기록을 거부하지 않는다.
  - snapshot 정리가 경로를 resolve해서 비교한다. Windows에서 같은 폴더를 다른 표기로 적어도 정리가 거부되지 않는다.
  - Windows npm `ocr.cmd`를 쓸 때 레포 경로에 `& | < > ^ % "`가 있으면 `prepare`가 멈춘다. 이전에는 cmd.exe가 경로를 명령으로 나눴다.
- **flow-gate 인박스 검사:** Edit·MultiEdit·search_replace의 부분 편집과 `apply_patch`의 Update hunk를 현재 파일에 적용한 결과로 역할 인박스를 검사한다. 패치의 삭제·이동도 검사한다. 기존 과제명 파일을 지우거나 옮기는 정리는 허용한다.
- **의존성 설치(`deps.py`):**
  - agy 스킬을 `~/.gemini/config/skills`, `~/.gemini/antigravity-cli/skills`, `~/.gemini/skills`에서 찾는다. `~/.agents/skills`는 보지 않는다.
  - grok은 `GROK_HOME`이 있으면 설치 기록과 스킬을 그 아래에서 찾는다.
  - `--no-refresh`로 실행해도 호스트 전용 스킬은 매번 다시 설치한다.
- **setup:** 아무 곳에서도 쓰지 않는 템플릿 폴더 6개를 만들지 않는다. `.fullops-squad/docs/design-docs/diagrams`, `.fullops-squad/docs/exec-plans/active`, `.fullops-squad/docs/exec-plans/completed`, `.fullops-squad/docs/exec-plans/discarded`, `.fullops-squad/docs/exec-plans/sprint-contracts`, `.fullops-squad/docs/planning/meeting-logs`다.
- **모션:** `render.mjs`는 렌더 중 ffmpeg가 죽으면 `render.mjs: ffmpeg exited <코드>`를 출력하고 종료코드 1로 끝난다. 이전에는 Node 오류로 끝나거나 멈출 수 있었다. 브라우저는 항상 닫는다.
- **fullops-meter 0.12.0:**
  - Flow 탭이 리뷰 키(예: `K1-DEV-REVIEW-R2`)를 과제 `K1`로 묶는다. 과제에 묶인 리뷰나 worker 중 하나라도 해당하면 `✖ review blocked`, `⚠ needs you`, `✖ agent gone`을 보인다.
  - 결정·flow 기록 파일은 크기나 수정 시각이 바뀐 것만 다시 읽는다. git 폴더 위치는 최대 1분에 한 번 다시 찾는다.
  - 1.16.0의 meter 변경(Orca 1.4.246 이후 출력 읽기)은 버전을 올리지 않아 기존 설치에 전달되지 않았을 수 있다. 0.12.0으로 함께 전달된다.

| 측정(개발 PC, Windows, 이 저장소) | 변경 전 | 변경 후 |
|---|---|---|
| lint 파일 읽기(경로 1,551개) | 46.50초 | 1.69초 |
| 도구 호출의 flow hook(tool, post 각각) | 약 1,000~1,100ms | 약 500~530ms |
| Stop의 flow hook | 약 1,700ms | 약 730ms |
| 검색 메타데이터 콜드 빌드(코드 범위) | 25.77초 | 1.02초 |

측정은 한 PC의 값이다. lint는 파일별 읽기와 일괄 읽기를 같은 범위에서 비교했다. hook은 12d7f8b와 d029a21을 비교했고, 그 뒤의 hook 변경은 측정에 들어 있지 않다. 검색 메타데이터는 다른 작업이 함께 도는 동안 1회 측정했다. 측정 기록은 이 저장소의 `.fullops-squad/docs/evaluations/qa-reports/{LINT-BATCH-READ,HOOK-SLIM,CLEANUP-FOLLOWUPS}-test/report.md`에 있다.

## 알아 둘 점

- **Git 2.41 이상이 필요하다.** lint와 Stop의 done-gate가 `git cat-file --batch -Z`를 쓴다. 더 낮은 Git에서는 lint가 실패한다. 기록·계획만 바꾼 커밋도 Stop에서 lint 통과를 다시 요구받는다.
- **Orca 1.4.246 이상을 전제로 한다.** 이슈 모드, 완료 기록(`integration.py`), flow-gate가 Orca 목록을 `--full`로 읽는다. 이슈 자동 모드를 쓰지 않아도 해당한다. 코드는 버전을 검사하지 않는다. 1.4.246 미만은 확인하지 않았다. 그런 Orca에서는 이슈 모드가 막히고, 리뷰어의 완료 보고를 다시 병합 대상으로 기록할 수 있다.
- **리뷰 기록의 역방향 호환:** 1.17.0이 만든 리뷰 기록은 LF 정규화 해시다. CRLF 체크아웃(`core.autocrlf=true`)에서는 1.16.1 이하의 `review.py check`가 이 기록을 거부한다. 1.16.1 이하가 만든 기록은 1.17.0에서도 통과한다. 줄끝만 다른 파일은 이제 같은 파일로 본다.
- **flow-gate의 새 거부:** Edit·MultiEdit·`apply_patch`로 진행 중인 역할 인박스(`handovers/to_<역할>.md`)를 비우거나, 다른 과제 제목으로 바꾸거나, 패치로 지우거나 옮기면 막는다. 1.16.1은 이 부분 편집을 검사하지 않았다. 인박스는 `work.py finish`로 비운다.
- Stop 대기 완화는 Stop 입력에 `background_tasks`를 보내는 Claude Code에서만 동작한다. Claude Code 2.1.319에서 확인했다. 이 필드가 없는 이전 버전은 이전처럼 포그라운드 대기를 안내받는다. 대기 명령에 Run ID를 셸 변수로 넘기면 이 Run의 대기로 인식하지 못해 Stop을 한 번 막는다.
- Stop 경로의 현황판 이슈 목록은 최대 5분 늦을 수 있다.
- 업데이트 뒤 첫 Jev 검색은 스키마가 바뀐 캐시를 버리고 메타데이터를 다시 만든다.
- 미종료 이슈 attempt가 있는 동안 Orca 조회가 실패하면, dispatch된 worker의 도구 호출이 거부된다(fail closed). 이슈 Run에 속한 worker는 task spec을 읽지 못해도 거부된다. 이슈와 무관한 worker는 범위가 바뀌지 않으면 한 번 확인한 결과를 다시 쓴다.
- `reconcile --not-dispatched`로 intent를 닫으면 attempt 하나를 쓴다. 기본 `max_attempts`는 3이다. 닫기는 자동으로 일어나지 않고 coor가 근거와 함께 실행한다.
- `set-sha`는 저장된 SHA를 덮어쓴다. `--key`를 주면 과제 키도 덮어쓴다. hold한 기록은 `resume`을 따로 실행한다.
- 배정 검사는 여전히 명령 실행 전 파일을 본다. 인박스 작성과 `worker-start`는 별도 명령으로 실행한다.
- POSIX에서 lint의 시험 명령은 새 세션으로 돈다. `nohup`으로 띄운 lint도 이제 터미널이 닫히면 중단된다. 이때 결과와 통과 기록은 쓰지 않는다.
- 인코딩 도중 ffmpeg가 죽으면 일부만 쓴 MP4가 남을 수 있다. `render.mjs`는 이미 있는 출력 경로를 거부하므로, 다시 렌더할 때는 새 vNN 경로를 쓴다.
- 기존 agy 설치에서 FullOps 스킬이 `~/.agents/skills`에만 있으면 `deps.py --check --host agy`가 `agy: skill: <이름>`과 종료코드 1로 끝난다. 실제 agy 세션으로는 확인하지 않았다.

## 기존 설치 적용

- 플러그인을 1.17.0으로 갱신한 뒤 새 패키지의 `scripts/deps.py --host <현재 CLI>`를 실행한다. 이어서 `scripts/deps.py --check --host <현재 CLI>`로 확인한다. Claude Code는 사용자가 `/reload-plugins`를 실행한 뒤 같은 세션에서 이어간다. Codex·grok은 새 세션을 시작한다.
- `git --version`이 2.41 미만이면 Git을 올린다.
- Orca를 1.4.246 이상으로 둔다. 이슈 자동 모드를 쓰지 않아도 완료 기록과 flow-gate가 이 버전을 전제로 한다.
- 같은 레포에서 리뷰를 다루는 모든 PC와 에이전트를 1.17.0으로 올린다. 이전 버전은 CRLF 체크아웃에서 새 리뷰 기록을 거부한다.
- agy를 쓰는 PC에서는 `scripts/deps.py --check --host agy`를 실행한다. 출력에 `agy: skill: <이름>`이 있으면 `scripts/deps.py --host agy`로 다시 설치한다.
- `GROK_HOME`을 쓰는 grok은 `scripts/deps.py --host grok`를 다시 실행해 `$GROK_HOME/fullops-deps.json`을 만든다.
- fullops-meter를 설치한 Claude Code는 `claude plugin marketplace update fullops-squad`를 실행한다. 이어서 `claude plugin update fullops-meter@fullops-squad --scope user`를 실행한다. 0.12.0은 새로 시작한 세션부터 적용된다.

## 기존 레포 적용

필수 항목은 없다. 아래는 해당할 때만 한다. 스크립트 경로는 설치된 플러그인 기준이다.

- 위 `setup` 항목의 6개 폴더 중 `.gitkeep`만 있는 폴더는 지운다. 다른 파일이 있는 폴더는 그대로 둔다. setup을 다시 실행해도 이 폴더를 지우지 않는다.
- PLANS.md의 보류 기록에서, SHA가 없어 hold한 완료 기록의 메시지 ID를 찾는다. worker에게 완료 SHA를 확인한다. `scripts/integration.py --repo <레포 루트> set-sha --message <ID> --sha <SHA>`로 SHA를 기록한다. 이어서 `scripts/integration.py --repo <레포 루트> resume --message <ID>`로 hold를 푼다.
- 1.16.1과 Orca 1.4.246 이상으로 운영했으면 `scripts/integration.py --repo <레포 루트> status`를 실행한다. `pending`의 각 항목이 리뷰어의 보고인지 확인한다. 확인 방법은 그 보고를 보낸 task의 spec에 `Purpose: review`가 있는지 `orca orchestration task-list --run <run> --full --json`으로 보는 것이다. 리뷰어의 보고면 `scripts/integration.py --repo <레포 루트> hold --message <ID> --reason <사유> --owner <담당> --resume <재개 조건>`으로 닫는다. 1.17.0은 기존 기록을 자동으로 지우지 않는다.
- 이슈 자동 모드에서 시작되지 않은 dispatch intent 때문에 다른 이슈의 claim이 막혀 있으면, 먼저 실제 미시작을 확인한다. 그다음 `python3 scripts/issue_mode.py --repo <레포 루트> --orca <Orca 실행 파일> reconcile --not-dispatched --token-file <lease JSON> --issue-id <id> --reason <근거>`로 intent를 닫는다. 이슈는 held가 된다. 재시도는 `python3 scripts/issue_mode.py --repo <레포 루트> --orca <Orca 실행 파일> checkpoint --token-file <lease JSON> --issue-id <id> --phase queued --reason <근거>`로 한다.
- Windows에서 npm `ocr.cmd`를 쓰고 레포 경로에 cmd 메타문자(`& | < > ^ % "`)가 있으면, 리뷰를 준비하기 전에 경로를 바꾼다.

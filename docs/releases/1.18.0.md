# 1.18.0 — 작업 검증 명령, 자주 틀리는 것, verifier 절차

#82 로드맵의 P2(자체 검증·verifier)를 반영했다. 완료를 말로 보고하지 않고 실제 명령 출력으로 보이게 하고, 같은 실수를 기록으로 쌓고, 새 문맥의 독립 실행을 절차로 정의한다. 새 hook 차단과 lint 강제는 없다. 코드 변경도 없고 문서와 시험만 바뀌었다.

## 변경

- **`project.md`:**
  - `## 작업 검증` 절을 추가했다. 대표 명령과 실행 위치, 합격을 판정하는 기대 출력을 적는다. 지시서의 `증명 방법`이 따로 정하지 않으면 이 명령을 쓴다.
  - `## 자주 틀리는 것` 절을 추가했다. 같은 실수가 두 번째 나오면 한 줄을 추가한다. 첫 발생은 `contexts/<역할>.md`의 교훈으로 남긴다.
- **지시서 템플릿(`handovers/_TEMPLATE.md`):**
  - `증명 방법` 줄이 명령과 기대 출력을 요구한다. 완료 보고의 검증 항목에 실제 출력 발췌를 붙인다. 합격을 판정하는 줄 위주로 최대 5줄이며, 비밀값은 지운다.
  - `verifier` 줄을 추가했다.
  - `## 완료 보고` 절은 바꾸지 않았다. 진행 중 인박스의 미작성 보고를 `work.py finish`가 계속 거부한다.
- **`rules/delegation.md`:** `## 검증 하위 작업(verifier)` 절을 추가했다. 새 문맥에서 변경을 실행하고 고치지 않고 보고만 하는 읽기 전용 하위 작업이다.
  - 대상: `test_level`이 standard 이상인 동작 변경 과제의 기본 절차다. lite는 지시서가 지정한 과제만 실행한다. minimal, 문서·문구만 바꾼 변경, tester 독립 QA가 배정된 과제는 제외한다.
  - 범위: standard 이상은 변경 동작과 인접 흐름 2개, lite는 핵심 동작과 실패 경계다.
  - 순서: 구현 커밋의 lint 통과 뒤, 완료 보고 전에 1회 실행한다.
  - 실행하지 않으면 사유를 완료 보고에 적는다. 직접 작업은 `report.md`에 적는다.
  - lite 지시 검사가 거부하는 표현을 함께 적었다. 예시로 인용한 문구도 걸린다.
- **`fullops-work` 스킬:**
  - 완료 보고의 출력 발췌 규칙을 추가했다. lint에 등록된 명령은 다시 실행하지 않고 `lint-result.json`의 `output_tail`에서 옮긴다. skipped됐거나 출력이나 결과 파일이 없으면 직접 실행한다.
  - 직접 작업은 발췌를 `report.md`에 적는다.
  - 반복 실수 규칙을 "두 번째 나오면 `자주 틀리는 것`에 추가, 정규식으로 잡을 수 있으면 `lint.json` `rules` 제안"으로 바꿨다.
- **`fullops-test`, `setup-fullops` 스킬과 README:** 새 절을 가리키는 문장을 추가했다. setup은 기대 출력을 실제 실행 결과에서 옮긴다.
- **`lint/README.md`:** `output_tail` 설명을 코드에 맞췄다. 이전 문서는 실패·시간 초과 출력만 남긴다고 적었지만, 실제로는 실행한 모든 명령의 마지막 40줄을 남긴다.

## 알아 둘 점

- `subagent_level`이 `off`이면 verifier는 실행되지 않고 미실행 사유만 남는다. 설정이 없는 기존 레포의 기본값이 `off`다.
- 신규 setup의 기본값은 test `lite`다. 그래서 신규 레포에서는 지시서가 지정한 과제만 verifier를 실행한다. 인접 흐름까지 확인하려면 `test_level`을 standard로 올린다.
- verifier는 호스트 서브에이전트로만 실행한다. 자동 이슈의 owner·연결 worker는 호스트 서브에이전트를 쓸 수 없어 실행하지 않고 사유를 적는다.
- verifier의 읽기 전용은 지시 계약이고 샌드박스가 아니다. 시험이 작업 트리를 바꿀 수 있으므로 부모가 `git status`로 확인한다.
- verifier는 tester 독립 QA, `review.py need`가 요구하는 독립 리뷰, 최종 수락을 대체하지 않는다.

## 필수 적용

update-fullops는 이 절의 항목을 해당 없음·보류로 분류하지 않는다. `update.py --verify`가 통과해야 `plugin_version`을 1.18.0으로 올린다. 제목이 있는지만 확인하며, 값이 `미확정`이어도 통과한다.

- 작업 검증 절 — 확인: `.fullops-squad/project.md`에 `## 작업 검증`
- 자주 틀리는 것 절 — 확인: `.fullops-squad/project.md`에 `## 자주 틀리는 것`
- verifier 절 — 확인: `.fullops-squad/rules/delegation.md`에 `## 검증 하위 작업(verifier)`

## 기존 설치 적용

- 플러그인을 1.18.0으로 갱신한 뒤 새 패키지의 `scripts/deps.py --host <현재 CLI>`를 실행한다. 이어서 `scripts/deps.py --check --host <현재 CLI>`로 확인한다. Claude Code는 사용자가 `/reload-plugins`를 실행한 뒤 같은 세션에서 이어간다. Codex·grok은 새 세션을 시작한다.

## 기존 레포 적용

setup은 기존 문서를 덮어쓰지 않는다. 설치된 패키지의 `assets/repository/.fullops-squad/` 아래 같은 경로의 파일과 비교해 필요한 부분만 병합하고, 레포가 고친 내용은 보존한다.

- `.fullops-squad/project.md`에 `## 작업 검증`과 `## 자주 틀리는 것` 절을 `## 공통 기준의 적용과 예외` 앞에 넣는다.
- `작업 검증`을 채운다. 현재 `test_level`에서 실제로 도는 명령을 고른다. 실제 cwd에서 실행해 합격을 판정하는 출력 줄을 `기대 출력`에 옮긴다. 실행할 수 없으면 `미확정`과 사유를 적고 사용자에게 보고한다.
- `자주 틀리는 것`은 비워 두고 시작한다. `contexts/<역할>.md`나 리뷰 기록에 이미 두 번 이상 반복된 근거가 있는 실수만 적는다.
- `.fullops-squad/rules/delegation.md`에 `## 검증 하위 작업(verifier)` 절을 `## 이슈 오토모드` 앞에 넣는다. `subagent_level`과 `test_level` 값은 바꾸지 않는다.
- `.fullops-squad/FULLOPS.md`의 `기술 기준·검증 명령·문서 정본` 행을 `기술 기준·검증 명령·자주 틀리는 것·문서 정본`으로 바꾼다.
- `.fullops-squad/handovers/_TEMPLATE.md`의 `증명 방법` 줄과 `verifier` 줄을 맞춘다. 진행 중 인박스는 고치지 않는다.
- `.fullops-squad/lint/README.md`의 `output_tail` 설명과 `rules` 항목 문구를 병합한다. `## 규칙 변경 기록`과 `lint.json`은 그대로 둔다.

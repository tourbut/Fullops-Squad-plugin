# FullOps Squad 0.9.13

배포 승인 근거: 2026-10-03 사용자의 수정본 배포 요청.

## 변경

- 셸 명령별로 도움말과 실제 배정을 구분한다. 도움말 뒤의 실제 배정·긴 터미널 작업 지시는 기존 검사를 유지한다. PowerShell spec 변수와 here-string의 과제 키를 읽는다.
- 문장 끝 마침표를 작업 키의 구분자로 인정한다. 접미사가 다른 키는 같은 작업으로 인정하지 않는다.
- path·id 워크트리 선택자를 실제 경로로 해석한다. active·current·name·branch 선택자는 Orca에서 조회하며 최신 기본 브랜치 검사를 유지한다.
- 직접 check를 사용하면 지정된 Run과 coordinator 터미널로 완료 보고를 수집한다.
- 한국어 SHA 보고와 영어 Local commit 보고에서 최종 커밋을 읽고 Orca 과제 정보로 작업 키를 보완한다. 여러 커밋이 있어 모호한 보고는 자동 선택하지 않는다. 재수신 시 빈 필드만 보완하고 보류 사유를 보존한다.
- hold·resume의 완료 기록이 없으면 메시지를 peek로 다시 조회한다. 조회에도 없으면 traceback 대신 Run·터미널을 지정하는 재시도 방법을 안내한다.
- 종료 시 현재 체크아웃과 설정된 기본 브랜치의 PLANS·인박스·날짜별 하위 완료 로그를 확인한다. 오래된 coordinator 체크아웃 때문에 이미 처리한 작업을 미배정으로 오인하지 않는다.

## 기존 레포 적용

글로벌 플러그인을 업데이트하고 새 에이전트 세션을 사용한다. 역할·기본 브랜치·서비스 코드를 변경할 필요는 없다. 진행 중 worker의 파일과 체크아웃을 그대로 유지한다.

0.9.12에서 SHA·작업 키가 비어 저장된 완료 보고는 원본 메시지를 다시 수집할 때 보완한다. ACK 전 보고라면 integration.py hold 또는 resume에 --run과 --terminal을 지정해 조회할 수 있다. 이미 ACK한 보고는 원본 완료 메시지와 로그를 확인하고 복구한다. 기존 hold의 사유·담당자·재개 조건을 유지하며 사용자 병합·push 제한을 해제하지 않는다.

업데이트 적용 기록에 해당 오류의 재발 여부와 이전 릴리스 미적용 항목을 남긴다. npm 설치기는 변경이 없어 0.9.11을 유지하며 최신 GitHub 플러그인을 받는다.

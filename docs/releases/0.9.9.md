# FullOps Squad 0.9.9

## 범위

0.9.8 배포에 누락된 제품 기획·DEV 라우팅 패치를 복구한다.
기획자는 제품 목표와 규칙을 정한다. DEV는 기술 계획·구현·테스트·기술 문서 갱신을 같은 과제에서 수행한다.
0.9.8의 front matter, 한국어 STE 작성 원칙과 Jev 문서 검색은 유지한다.

## 변경

- 라우팅 기준의 제품 기획·기술 계획 marker로 새 구조를 명시적으로 활성화한다.
- 확정된 제품 요구 안의 기술 작업은 `implementation`으로 담당 worker에 배정한다.
- 제품 규칙 결정·범위 확대·공유 제품 기준의 불명확성은 `product`로 기획자에게 배정한다.
- 호출 실패·낮은 확신은 `unresolved`로 보류한다. 역할 변경은 근거를 기록한다.
- coordinator가 구현 지시서를 작성할 수 있도록 hook과 스킬을 맞춘다.
- hook은 `apply_patch` 본문의 실행 예시를 실제 명령으로 처리하지 않는다.
- 역할 전환에서 기존 `fullops/*` 브랜치를 재사용한다. 역할별 브랜치 중복은 거부한다.
- 새 구조의 리뷰는 서로 다른 세션 ID와 별도의 깨끗한 detached snapshot을 요구한다.
- 리뷰 검사는 snapshot의 고정 SHA와 체크아웃 루트를 확인한다. 새 리뷰 스키마 제거도 거부한다.
- 기존 `simple/design` 라우팅과 전환 전 리뷰 기록은 유지한다.

## 기존 레포 적용

플러그인을 업데이트하고 새 세션을 연다. setup은 기존 문서를 덮어쓰지 않으므로 변경한 템플릿을 직접 비교한다.
역할·브랜치·진행 과제·검증 기록을 보존한다. 새 구조는 marker 두 줄을 추가한 뒤 활성화된다.

erden-godot은 현재 `designer: fullops/arch`, `dev: fullops/dev`를 사용한다.
`설계 역할: designer`는 있지만 제품 기획·기술 계획 marker는 없다. 다음 지시문으로 레포를 갱신한다.

### erden-godot main 세션 지시문

```text
erden-godot을 FullOps Squad 0.9.9에 맞춰 갱신해.
1. 설치된 플러그인 버전과 deps.py --check 결과를 확인해. 0.9.9가 아니면 README의 현재 CLI 업데이트 명령으로 갱신해.
2. 레포와 각 워크트리의 변경·진행 과제를 확인해. 기존 변경과 검증 기록을 보존해.
3. 설치된 setup-fullops 스킬을 읽고 현재 역할로 setup dry-run과 실행을 진행해. 기존 문서는 새 템플릿과 비교해 필요한 부분만 반영해.
4. fullops.json의 designer: fullops/arch와 나머지 역할별 브랜치를 유지해. arch 브랜치나 워크트리를 새로 만들지 마.
5. orca-agents.md의 ## 라우팅 기준에 다음 두 줄을 추가해.
   - 제품 기획 역할: `designer`
   - 기술 계획 역할: `dev`
   기존 coordinator 역할: coor, 설계 역할: designer, tester 역할: tester는 유지해.
6. designer는 제품 목표·규칙·수치·아트 방향·우선순위·완료 조건을 결정하게 해. DEV는 기술 계획·구조/API·버그 분석·구현·테스트·기술 문서 갱신을 맡게 해.
7. FULLOPS.md와 역할 문서에서 상시 기술 승인·상세 구현 계획을 designer에게 요구하는 기존 규칙을 새 책임에 맞춰 수정해. 독립 코드 리뷰·동작 QA·ART 직접 검수·미해결 critical/high 차단은 유지해.
8. 문서의 front matter와 한국어 STE 작성 원칙을 유지해. 새 구조의 독립 리뷰는 별도 세션과 고정 SHA의 깨끗한 detached snapshot을 사용해. 전환 전 리뷰 기록은 수정하지 마.
9. dry-run·역할 판정·브랜치 중복 여부와 기존 진행 자료 보존을 확인해. 적용이 끝나면 plugin_version을 0.9.9로 갱신하고 준비 변경을 커밋·push해.
10. 쉬고 있고 깨끗한 worker 브랜치에만 준비 커밋을 동기화해. 작업 중인 브랜치는 완료 후 동기화하도록 기록해.
11. 준비 커밋 SHA, 변경한 문서, 적용된 marker와 보류한 동기화를 보고해. 새 coor 세션에 이어받을 자료를 남겨.
```

### erden-godot 새 coor 세션 지시문

```text
FullOps Squad 0.9.9의 제품 기획·DEV 구조로 작업을 이어받아.
1. 설치 버전과 main 준비 커밋을 확인해. 자기 체크아웃의 fullops.json·orca-agents.md·FULLOPS.md·PLANS.md를 읽어.
2. 제품 기획 역할: designer와 기술 계획 역할: dev marker를 확인해. 없으면 운영 동기화 과제로 처리해. 진행 자료를 보존하고 작업 중인 브랜치에는 강제 반영하지 마.
3. 신규 코드·산출물 과제는 jev_route.py로 분류해. implementation은 기술 난도와 무관하게 담당 worker에, product는 designer에 배정해.
4. unresolved는 책임과 제품 범위를 확인한 뒤 --override-role과 --reason으로 근거를 남겨. 기존 결과 재선정은 --force로 원본을 보존해.
5. 구현 지시서에는 목표·확정 규칙·범위·완료 조건·정본 링크를 짧게 적어. DEV가 기술 계획부터 구현·테스트·문서 갱신까지 수행하게 해.
6. 기존 요구 안의 기술 판단은 DEV가 해결하게 해. 제품 규칙 변경·범위 확대·공유 제품 기준 불명확성만 designer에게 전달해.
7. 정상 worker는 worker_done 중심으로 기다려. 완료 메시지의 SHA·검증 요약·남은 일로 다음 배정을 정해. 실패·누락·충돌 때 원본 증거를 확인해.
8. 병합 전에는 고정 SHA의 독립 리뷰·lint·테스트 게이트를 확인해. 독립 리뷰의 서로 다른 세션 ID와 깨끗한 detached snapshot을 기록해.
9. 기존 과제·승인·QA 기록과 ART 직접 검수 기준을 보존해. 워크트리 이름 변경 때문에 과제나 검증을 복제하지 마.
10. 이어받은 과제, 새 구조 적용 상태와 다음 배정을 짧게 보고한 뒤 진행해.
```

## 검증

`npm ci`, `npm test`, `npm run test:review`, native 빌드와 호스트 패키지 검증을 실행한다.
회귀 검사는 새 라우팅·불확실한 요청의 배정 차단·역할 변경 근거·브랜치 별칭 보존을 확인한다.
실제 OCR delegate 검사는 세션 분리·스키마 보존·고정 SHA·detached 상태·snapshot 변경 차단을 확인한다.

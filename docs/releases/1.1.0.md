# 1.1.0 — 선택형 GitHub 이슈 작업 모드

## 변경

- `fullops-issues`는 FullOps 활성 서비스 저장소에서 사용자 요청으로만 설정/활성화한다. 기본 OFF. 저장한 allowlist는 GitHub stable user ID 기준이고 실행 직전 재확인한다. 기본 300초, 최소 60초이며 backlog는 명시 선택한다.
- stdlib 로컬 폴러가 PR 제외, pagination/ETag/304, timestamp 겹침, backoff, durable enqueue를 처리한다. 같은 저장소의 SQLite transaction과 session/run/terminal incarnation lease가 FIFO 단일 claim을 지킨다. 주기마다 모델/Jev를 호출하지 않는다.
- 동일 coor의 foreground wait와 기존 Orca check를 사용한다. TUI terminal agent는 native SessionStart의 host session/terminal binding, structured session은 live caller로 소유자를 검증한다. 화면에서 선택된 pane 대신 소유 handle의 Run/incarnation을 조회한다. 다른 coor 생성·전환이나 PTY 입력을 하지 않는다. busy 동안 수집만 하고, 종료/미확인 lease 만료 뒤 새 dispatch를 차단한다. 새 세션의 명시 활성화는 이전 task/worker를 reconciling으로 보존한다.
- 원래 이슈의 질문은 durable outbox/comment ID/발신 표식으로 전송 결과를 조정한다. 원 작성자의 새 답변만 묶어 coor에 전달하고 충분성/충돌 판단을 기록한 뒤 새 attempt/digest로 재개한다. 질문 POST 결과가 불명확하면 댓글 조회 결과만으로 재게시하지 않는다.
- 기존 route/handover/packet/lint/독립 리뷰를 재사용한다. 완료는 같은 저장소의 현재 SHA를 가진 draft PR까지이며 main 병합/push, 배포, 이슈 종료는 포함하지 않는다. 기존 자동 병합 대신 integration hold로 사용자 판단을 남긴다.

## 적용

1. 플러그인을 업데이트한 뒤 새 세션을 연다. 스킬/코드 설치로 자동 모드가 켜지지 않는다. 기본 운영은 그대로다. npm 설치기 wrapper 버전은 별도로 관리한다.
2. 사용자가 서비스 저장소에서 이슈 자동 모드를 요청하면 `fullops-issues`의 초기 질문을 따른다. 확인된 remote/base, GitHub push/댓글 권한, 현재 coor의 session/terminal/Run 증거와 native SessionStart receipt가 필요하다.
3. 정상 작업 범위와 재시도/시간/사용량 한도를 선택한다. 모델 토큰 한도는 확인한 사용량을 checkpoint에 기록한다. 호스트가 사용량을 제공하지 않으면 임의의 0을 쓰지 않고 보류한다.
4. SessionEnd를 지원하는 호스트는 종료 hook으로 OFF를 기록한다. 종료 hook이 없거나 crash하면 90초 lease 만료로 차단한다. 실제 worker는 무조건 종료/삭제하지 않는다.

## 검증과 한계

`python3 tests/issue-mode.py`는 격리 Git 저장소에서 수집/중복/동시 claim/lease/fencing, 작성자 ID, 질문 응답 유실/같은 계정/답변 판단/새 attempt, 변경/삭제, scope와 review 실패를 실행한다. GitHub 응답과 live coor는 결정적 대역을 사용하므로 실제 wake 증거로 취급하지 않는다.

Windows Orca 1.4.222의 실제 status/terminal/check 명령을 확인했다. TUI terminal agent에는 `caller.orcaSessionId`가 제공되지 않아 native host session/terminal binding 검증을 추가했다. 현재 대화는 setup/native SessionStart receipt가 없어 활성화하지 않았다. 별도 QA CODEX_HOME에서 native Codex 0.160.1 app-server가 SessionEnd 포함 9개 hook을 경고·오류 없이 로드했다. 실제 연결된 coor의 idle/busy 수신 receipt와 GitHub 질문→작성자 답변→같은 coor 재개는 별도 실환경 수용 검증이 필요하다. 이 릴리스 기록은 그 검증의 성공이나 이슈 #10 완료를 주장하지 않는다. 상세 운영/검증 기록은 [issue-auto-mode.md](../issue-auto-mode.md)를 따른다.

flow-gate는 인식하는 명령·파일의 추가 범위 검사이며 셸/외부 도구를 완전히 격리하는 보안 경계가 아니다. 사용자/호스트 권한·샌드박스·승인 정책을 유지하고 범위 밖 요구는 보류한다. 상태는 Git 공용 디렉터리 `fullops-issues/state.sqlite`에 있으며 인증 토큰을 저장하지 않는다. event/queue는 소규모 단일 저장소용이고 대규모 backlog/외부 webhook/자동 호스트 재시작은 포함하지 않는다.

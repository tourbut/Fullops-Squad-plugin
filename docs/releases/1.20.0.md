# 1.20.0 — 주요 흐름 고정 세트와 통합 후보 기본값

#82 로드맵의 P4(지속 평가)를 반영했다. 고정 세트 규칙은 1.8.3부터 있었으므로 새 절차를 더하지 않고, 그 규칙의 빈 곳과 충돌을 고쳤다. 코드 변경도 새 강제도 없고 문서와 시험만 바뀌었다. 공통 규칙 묶음은 `fullops-common-0.3.7`이다.

## 변경

- **`project.md`:** `## 주요 흐름` 표(흐름, 실행 수단)를 추가했다. 빈 표로 시작하고 큰 틀 검수에서 실제로 돌린 흐름만 올린다. 10개를 넘으면 담당이 빼거나 합칠 흐름을 제안한다.
- **`rules/common/testing.md`(`담당과 반복 범위`):**
  - 통합 후보의 기본값을 정했다. 지시서나 사용자가 정하지 않으면 묶음의 과제가 모두 병합된 기본 브랜치 SHA이고, 묶음이 없으면 현황판 단계가 끝난 때의 SHA다.
  - 세트의 정본을 `docs/evaluations/scenarios/` 폴더에서 `주요 흐름` 표로 옮겼다. 시나리오 폴더는 실행 수단의 하나로 남는다.
  - 각 흐름은 프로젝트 E2E 명령, 시나리오, 재실행 절차 중 비용이 가장 낮은 수단으로 돌린다.
  - `minimal`은 별도 차수 없이 coordinator가 직접 한 번 돌린다. 기존 문구에는 레벨 조건이 없어 `minimal` 규칙과 충돌했다.
  - 세트에 추가하는 결함을 좁혔다. 코드 시험으로 재현할 수 없는 흐름 결함과 재발한 결함만 추가하고, 그 밖의 결함은 재현 테스트로 남긴다.
- **`fullops-orca` 스킬:**
  - 통합 후보의 `lint.py --level full`에 `--from <직전 통합 후보 SHA>`를 적었다. 이전 문구는 `--from`을 정하지 않아, 변경이 없는 기준으로 돌리면 full 시험이 하나도 돌지 않고 종료코드 0으로 끝날 수 있었다. 통합 후보 SHA도 PLANS.md에 적는다.
  - 병합 6단계에 큰 틀 검수 배정 시점을 적었다.
- **`lint/README.md`, `FULLOPS.md`, `scenarios/README.md`, intent 템플릿:** 새 표를 가리키는 문장을 추가했다.

## 알아 둘 점

- 플레이북의 eval은 제품 회귀가 아니라 에이전트 구성(CLAUDE.md, 스킬, 훅)을 바꿀 때 에이전트가 같은 수준으로 일하는지 재는 장치다. FullOps는 이 장치를 반영하지 않았다. 이번 표는 제품의 주요 흐름 회귀이며 플레이북 eval의 직역이 아니다.
- 그래서 플레이북의 20~50개, 야간 실행, 통과율 기반 병합 검사는 옮기지 않았다. 10은 보고서에 흐름당 한 줄을 넣을 수 있는 규모라는 판단이며 실측값이 아니다. 세트 1회의 비용은 측정한 적이 없다.
- 고정 세트가 회귀를 더 잘 잡는다는 근거는 아직 없다. 묶음 실행기, 세트 채우기, 사례 은퇴 규칙은 넣지 않았다. 세트 재실행의 커밋 범위도 바꾸지 않아, Jev 실행마다 폴더 하나의 파일 3개가 커밋된다.
- 큰 틀 검수 보고서가 길어지는 문제는 이 변경으로 해결되지 않는다.
- hook·lint·게이트는 추가하지 않았다. 병합에서 검수로 넘어가는 전환(E13)은 지침 문장만 있고 자동으로 옮기지 않는다.
- 진행 중 과제에는 소급하지 않는다.

## 필수 적용

update-fullops는 이 절의 항목을 해당 없음·보류로 분류하지 않는다. `update.py --verify`가 통과해야 `plugin_version`을 1.20.0으로 올린다. 제목과 문구가 있는지만 확인하며, 표가 비어 있어도 통과한다.

- 주요 흐름 표 — 확인: `.fullops-squad/project.md`에 `## 주요 흐름`
- 세트 정본과 통합 후보 기본값 — 확인: `.fullops-squad/rules/common/testing.md`에 `표에 고정 세트로 유지`
- 규칙 묶음 — 확인: `.fullops-squad/rules/common/README.md`에 `fullops-common-0.3.7`

## 기존 설치 적용

- 플러그인을 1.20.0으로 갱신한 뒤 새 패키지의 `scripts/deps.py --host <현재 CLI>`를 실행한다. 이어서 `scripts/deps.py --check --host <현재 CLI>`로 확인한다. Claude Code는 사용자가 `/reload-plugins`를 실행한 뒤 같은 세션에서 이어간다. Codex·grok은 새 세션을 시작한다.

## 기존 레포 적용

setup은 기존 문서를 덮어쓰지 않는다. 설치된 패키지의 `assets/repository/.fullops-squad/` 아래 같은 경로의 파일과 비교해 필요한 부분만 병합하고, 레포가 고친 내용은 보존한다.

- `.fullops-squad/project.md`에 `## 주요 흐름` 절을 `## 자주 틀리는 것` 앞에 넣고, 규칙 묶음 표기를 `fullops-common-0.3.7`로 올린다. 표는 비워 두고 시작한다. 큰 틀 검수에서 이미 반복해 돌린 흐름이 기록에 있으면 그 흐름만 올린다.
- `.fullops-squad/rules/common/testing.md`의 `담당과 반복 범위` 절 문장과 `rules/common/README.md`의 규칙 묶음을 맞춘다.
- `.fullops-squad/FULLOPS.md`의 문서 안내 행, `.fullops-squad/lint/README.md`의 `--level full` 문장, `docs/evaluations/scenarios/README.md`, `docs/planning/intents/_TEMPLATE.md`의 `확인할 흐름` 문장을 병합한다. 진행 중 인박스와 이미 쓴 intent는 고치지 않는다.
- `lint.json`과 `test_level`은 바꾸지 않는다.

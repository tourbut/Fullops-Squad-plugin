# FullOps Squad 0.5.0 변경안

## 범위

에이전트가 코드 전체를 훑지 않도록, 지시서를 쓸 때 Jev로 코드 위치를 찾고 과제가 끝나면 실제 변경과 비교해 적중률을 쌓는다. 추천일 뿐 게이트로 쓰지 않는다.

## Jev 코드 탐색

- `scripts/jev_find.py find`: HEAD의 파일 목록과 파일 헤더 설명으로 코드 지도를 만든다. TypeSafe semantic_find 방식대로 Choice 한 질문으로 위치 순위를, 두 값짜리 존재 질문으로 "관련 코드 없음"을 판정한다. 255개를 넘으면 디렉터리를 먼저 고른다. 출력의 `paths:`를 `jev_context.py --paths`에 넘겨 keep/omit을 검증한다.
- `scripts/jev_find.py score`: 과제가 끝난 뒤 실제 변경 파일을 정답으로 recall·precision·존재 판정 정오·새 파일 수를 기록한다. `jev_context` 결과가 있으면 잘못된 제외 추천도 센다. `review.py check`가 이 계산을 자동으로 실행해 리뷰 디렉터리에 남기므로 빠지지 않는다.
- 지도는 에이전트 토큰 없이 매번 결정론적으로 만든다. 별도 인덱스 파일을 두지 않는다.

## 헤더 설명

- 새 코드 파일은 맨 위 docstring·주석 1~3줄에 무엇을 하는지 적는다. 이 설명이 지도의 품질을 정한다.
- lint DOC-001: 헤더 설명이 없는 새 코드 파일은 WARNING이다. 기존 파일에는 소급하지 않는다.

## 기존 레포 적용

1. 플러그인을 0.5.0으로 갱신하고 새 세션을 연다.
2. `OPENROUTER_API_KEY`가 있는 환경에서 지시서를 쓸 때 `jev_find.py find` → `jev_context.py` 순으로 `먼저 읽을 문서`를 정한다. 키가 없으면 기존처럼 검색한다.
3. 병합 전 리뷰의 `review.py check`가 `find.json`이 있는 과제의 적중률을 자동으로 남긴다. 리뷰 키가 과제 키와 다르면 `--task-key`를 넘긴다.
4. 기존 레포의 `lint/README.md`에는 DOC-001 행이 자동으로 추가되지 않는다. 필요하면 수동으로 통합한다.

## 검증과 한계

`npm test`에 `tests/jev-find.py`를 추가했다. stub 응답으로 지도 구성, 순위, 존재 판정, 디렉터리 2단계, 실패 처리, 실제 diff 대비 적중률 계산, CLI를 검증했다. 실제 Jev의 코드 검색 정확도, 255개 선택지 요청의 크기 한도, 존재 경계값은 측정하지 않았다. 헤더 설명이 없는 레포에서는 경로 이름만으로 판단하므로 정확도가 낮을 수 있다.

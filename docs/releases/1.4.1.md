# 1.4.1 — 외부 의존성 latest 설치 정책

## 변경

- 외부 npm 도구·MCP·선택형 프런트 도구는 `@latest`로 설치한다. 공통·호스트 전용·선택형 스킬은 공식 저장소의 최신 원문을 사용한다. 의존 플러그인은 해당 마켓플레이스를 갱신한 뒤 설치하고, Claude에서는 기존 설치도 업데이트한다.
- 명시적 설치·업데이트 요청에서는 과거 완료 기록이 있어도 외부 의존성을 다시 갱신한다. `--check`는 설치 파일·출처·패키지 정체성·실제 실행 상태와 완료 기록을 확인하며 네트워크 업데이트를 수행하지 않는다.
- 스킬 내용의 고정 commit·SHA와 도구의 고정 버전 비교를 제거한다. 기존 스킬 폴더 전체의 백업과 출처 검증, 선택형 도구의 로컬 설치·비활성화, npm lifecycle scripts 제한, origin·요청·독립 assertion·review/done 게이트는 유지한다.
- Playwright 실행 증거에는 실제 CLI·런타임·브라우저 버전을 계속 기록한다. 선택한 런타임의 실행 실패를 다른 실행기로 자동 우회하지 않는다.

## 기존 레포 적용

1. 플러그인을 업데이트하고 새 세션에서 설치된 패키지의 `scripts/deps.py --host <codex|claude-code|grok> --dry-run`으로 범위를 확인한다.
2. 같은 명령에서 `--dry-run`을 빼고 최신 의존성을 설치한 뒤 `--check --host <호스트>`로 확인한다. 기존 로컬 경로 설치로 스킬 출처가 미확인인 경우 공식 저장소에서 재설치하며, 기존 수정은 `fullops-skill-backups/`에서 확인한다.
3. 프로젝트가 선택한 프런트 도구만 `frontend.py`의 dry-run·로컬 설치·검사로 갱신한다. 실행 중 제품 프로젝트의 package/lock·기존 역할·모델·인증·hook/MCP 설정은 보존한다.
4. `update-fullops`로 이전 릴리스의 보류 항목과 이번 레포 적용을 기록한다. 필수 적용과 관련 검증이 끝났을 때만 레포의 `plugin_version`을 갱신한다.

## 검증과 한계

Linux에서 전체 회귀·패키징·실제 OCR 리뷰 게이트 검사, 두 브라우저 실행기의 정상/삽입 결함·stale DOM·가림·origin 검사, Playwright 요청 차단을 검증했다. 최신 디자인 스킬 네 개는 임시 프로젝트의 세 호스트 경로에 실제 설치했다. 로컬 Playwright CLI의 설치·반복·비활성화·실패 복구도 확인했다.

세 호스트의 인증된 동일 UI 과제·설치 수명주기 전체, CUAWright 생성 코드의 실행·독립 리뷰·시각 검수, 사람 라벨과 API/cold/warm 반복 비교, macOS 실환경은 미검증이다. #22·#23을 이번 변경으로 완료 처리하지 않는다. 상세 기록은 `docs/evidence/issue22-23-linux-2026-10-13/`에 있다.
